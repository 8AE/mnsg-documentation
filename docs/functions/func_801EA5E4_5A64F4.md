`func_801EA5E4_5A64F4` · **Function**

Copies a target object position into an existing chain head and initializes the real playable player's native pull movement.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x801EA5E4` | `0x005A64F4` | `.file_11` |

Native code size: **636 bytes**.

## Signature

```c
extern void func_801EA5E4_5A64F4(void *head, void *player, void *target);
```

## How it works

Reads target +0x18, then only object XYZ at +0x08/+0x0C/+0x10. It copies those values into the chain-head object. It does not retain the target pointer, traverse a target list, or invoke a target callback.

Sets unsigned 16-bit player work +0x00 to movement mode 3 and unsigned 16-bit work +0x02 to the heading toward the target. Float work +0x04 receives forced acceleration magnitude 1.5606060028 (IEEE-754 bits 0x3FC7C1F0). Heading is also stored at player +0x94.

Initializes both float player fields +0xE4 and +0xE8 to the native speed cap 18.7272720337 (IEEE-754 bits 0x4195D174). These cap values are separate from the acceleration in private work +0x04.

Immediately sets the playable object Y to target object Y minus 3. This is a vertical snap at latch, rather than a gradual upward pull.

Stores the rotated hand offset in head task +0x9C/+0xA0/+0xA4. Owner actions 0x77 or 0x78 use (0, 3, 11.5); the other inspected launch states use (0, 4, 14).

Sets head phase +0x60 to 2 for a latched chain, or 3 when already within its native completion threshold. Hides the head and marker objects through their byte +0x64.

The endpoint is a copied position. func_801CE870_58A780 generates the horizontal force from stored heading and acceleration; func_801CD310_589220 integrates and caps the resulting movement. Native pull travel remains horizontal after the initial Y snap; this helper does not continuously follow a moving target.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `head` | `void *` | Fully constructed live native chain-head task, including its marker object. |
| `player` | `void *` | Real playable owner with live object and private work area at task +0x5C. |
| `target` | `void *` | Target task whose +0x18 points to an object containing world XYZ. |

## Return value

No return value.

## Usage example

```c
#include "modding.h"

static float observed_latch_target[3];

RECOMP_HOOK("func_801EA5E4_5A64F4")
void observe_chain_latch(void *head, void *player, const void *target)
{
    const unsigned char *task = target;
    const unsigned char *object;
    (void)head;
    (void)player;
    if (!task) return;
    object = *(const unsigned char *const *)(task + 0x18);
    if (!object) return;
    observed_latch_target[0] = *(const float *)(object + 0x08);
    observed_latch_target[1] = *(const float *)(object + 0x0C);
    observed_latch_target[2] = *(const float *)(object + 0x10);
}
```

Observe the target consumed by an existing native latch. The hook copies coordinates during the call and retains neither target nor object addresses. Null checks do not replace the native caller's lifecycle and ownership guarantees.

## Notes

- This function mutates the real playable player and its chain. Never call it on a render-only player task or an uninitialized chain descriptor.
- The helper does not select a player action. The normal ground pull action is 0x73 and airborne pull action is 0x7A; native release actions are 0x74 and 0x7B respectively.
- The normal pull updater may call this helper on its first tick when signed 16-bit player work +0x30 is zero, using the selected native target at work +0x88. An already initialized custom latch must preserve that first-tick state or the updater can dereference a missing or stale selected target.
- The native pull arrival radius is approximately 8.660254 world units. Other solid-body contact can prevent reaching that radius and requires a compatible release condition.
- Copying an endpoint does not establish that the route is clear; retain native head collision, wall contact and release processing.
- Native movement state can select a lower cap: bit 0 of the unsigned byte at private work +0x18 makes func_801CD310_589220 use 4.0. The latch constants alone do not guarantee the distance traveled in a frame.
- The movement integrator has a special velocity-retention check for floor codes 0x0095 and 0x009A at player +0x98. It still reads raw controller magnitude D_800C7DBC under forced movement mode 3: a value below 0.1 can discard prior velocity before adding the current acceleration, preventing speed from accumulating. These numeric floor codes are not identified as named surface types here.
