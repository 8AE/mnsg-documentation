## How it works

The task uses actor/entity 0xCB and the common actor post; the same callback supports travelling attacks from all three combat phases.

Attack mode is stored in the low five bits at task +0xE8. Individual mode trajectories and transition equations remain unconfirmed.

Ring children initialized by func_080056FC_6B899C are allocated relative to this travelling projectile through func_8021DDE8_5D92B8 and func_802171A8_5D2678. They inherit the projectile object rotation, including roll +0x18 = 0x8000. The ring initializer keeps that roll; its mode-0x100 branch changes only pitch +0x14 to 0x0200.

## Notes

- Resolve the full ROM-qualified overlay symbol; a shared 0x080... address alone does not identify the loaded routine.
- Use a live task of the documented family. Task pointers and callback slots follow the 32-bit target ABI.
- A ring created with a different owner must retain the native projectile-owner rotation state. Substituting the visible boss as owner can otherwise replace the inherited 0x8000 roll with an ordinary boss angle.
