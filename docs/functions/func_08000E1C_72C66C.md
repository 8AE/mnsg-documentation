`func_08000E1C_72C66C` · **Function**

Initializes a native Mermaid training obstacle, reacts to collision status, and finishes its impact and debris lifecycle.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x08000E1C` | `0x0072C66C` | `.file_69` |

Native code size: **572 bytes**.

## Signature

```c
void func_08000E1C_72C66C(void *task, void *object);
```

## How it works

State is inline at task +0xD0: unsigned phase byte +0xD0, unsigned active byte +0xD1, and signed frame halfword +0xD4. Both entity halfwords +0x5C/+0x5E are initialized to 0x033A.

Phase 0 binds its native model and animation, sets collision bounds, configures damage kind 1 at task +0x4C, sets object scale and visibility, and enters active phase 1. Model binding and collision-bound setup are separate native operations.

Phase 1 rotates the object. Contact status mask 0x2200 emits positional sound event 0x013B, clears the active byte and selects impact phase 2. If object Y is below -468, it requests task deletion.

Impact phase 2 sets task velocity words +0x7C to 4 and +0x80 to -4 at frame 1. At frame 30 it constructs native debris and requests deletion.

The waterfall controller chooses obstacle birth positions from local random values every 40 active frames. Ordinary falling motion is applied after this obstacle callback by the common native actor lifecycle.

The native scheduler runs task callback slots +0x08, +0x0C and +0x10 in that order. Child inheritance installs func_8021925C_5D472C as the pre-callback and func_80218F30_5D4400 as the post-callback. The obstacle callback occupies +0x0C, so the common post-callback runs afterward.

The post-callback reaches func_80218E7C_5D434C, which applies gravity through func_8021C444_5D7914 before integrating position through func_8021B808_5D6CD8. Obstacle task flags +0x60 are initialized to 0x00C006E1, enabling gravity bit 0x00800000 and position-integration bit 0x00000200.

Gravity subtracts unsigned task byte +0x75 divided by 50 from floating vertical velocity +0x7C. The obstacle initializes that byte to 10, giving -0.2 velocity per native post-callback. The lower velocity clamp is -3 when task +0x64 bit 0x1000 is clear, or -6 when it is set.

With position-integration bit 0x00000200 enabled, the native integrator adds twice task velocities +0x78, +0x7C and +0x80 to object X, Y and Z respectively. The ordinary -3 terminal vertical velocity therefore produces -6 height units per scheduled update.

## Usage example

```c
extern void func_08000E1C_72C66C(void *task, void *object);

typedef void (*NativeTaskCallback)(void *, void *);

/* The native scheduler owns execution of this callback. */
NativeTaskCallback documented_callback(void)
{
    return func_08000E1C_72C66C;
}
```

This exposes callback identity without running initialization, rendering, movement, collision handling or result cleanup a second time. The resident overlay and native task lifetime remain required.

## Notes

- This callback has collision, audio, allocation and deletion side effects. Restoring an obstacle by manually calling it can duplicate those effects; the native scheduler owns its next turn.
- Use the verified task/object generation and resident File 69 identity. The same entity value is shared with the swimming proxy.
- Zeroing the velocity words inside the obstacle callback does not hold its position: the later native post-callback reapplies gravity and moves Y by -0.4 from zero velocity. Any deliberate hold must account for that post-callback order and preserve unrelated native motion and collision flags.
