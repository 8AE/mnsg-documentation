`func_80034E08_35A08` · **Function**

Creates and inserts a native scheduler task with an update callback.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80034E08` | `0x00035A08` | `.main` |

Native code size: **48 bytes**.

## Signature

```c
extern void *func_80034E08_35A08(void *task_list, void (*update)(void *, void *),
                                 unsigned short flags);
```

## How it works

Calls the task allocation helper, then adjusts the scheduler links through an insertion helper. The second helper returns the task pointer and assembly preserves that value in v0 through return.

The new task belongs under the supplied engine owner/list. Its update callback is independent of playable-character behavior; attaching a model object later creates visual state without creating player input or AI.

Tasks use a flat depth-first scheduler list: +0x00 is the next task, +0x04 is the backlink and +0x20 is the 16-bit depth. A subtree ends when a following task has depth less than or equal to its parent. The halfword at +0x22 is scheduler flags, not an allocation generation counter.

A retained display task must still have consistent scheduler links and its expected update callback before reuse. Hiding and retaining a live child avoids repeated allocation during a pause; the engine owns destruction of the parent subtree.

The first task is named by the word at D_8006D328_6DF28. Its backlink may point to itself or cache the tail; it is not an ordinary predecessor link. Validate that head separately before applying a predecessor-next check to other tasks. FUN_80034B58 and FUN_80034D24 maintain these special head links.

The allocation leaf FUN_80034B58(parent, callback, file) resets a new record through FUN_80034A10, inserts it immediately at parent +0x00 with depth parent +1, and then returns; allocation failure leaves the link unchanged. The later insertion helper may reorder siblings. The scheduler FUN_80034734 calls FUN_8001481C(task) once before each runnable task: that helper selects the task file/segment, then the scheduler invokes pre/update/post callbacks at +0x08/+0x0C/+0x10. Callback changes within a task do not mean that its allocation lifetime changed.

## Parameters

| Parameter | Type | Description |

## Return value

Created/inserted task pointer, or null on allocation failure.

## Usage example

```c
extern void *func_80034E08_35A08(void *task_list, void (*update)(void *, void *),
                                 unsigned short flags);

static void model_update(void *task, void *object) {
    (void)task;
    (void)object;
}

void *make_model_task(void *owner) {
    if (!owner) return 0;
    return func_80034E08_35A08(owner, model_update, 0);
}
```

## Notes

- Keep the owner valid and check allocation failure.
- A non-null pointer alone does not prove a retained task is still linked after pool reuse.
