`func_08000FCC_708A0C` · **Function**

Runs the balloon’s native visual lifecycle and its single cosmetic pop branch.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x08000FCC` | `0x00708A0C` | `.file_48` |

## Signature

```c
void func_08000FCC_708A0C(void *task, void *object);
```

## How it works

Phase 0 initializes the visual model, scale, and position. Phase 1 has no callback body; it does not follow the rising target or play an animation clip.

In phase 2, the callback plays its pop sound, attempts to create a File 48 flash, and on successful flash creation emits native particles and three common debris children. It then deletes the balloon task. The pop path contains allocations, random-number use, sound, and deletion.

The rising target’s result-4 path advances the local balloon phase once through func_0800126C_708CAC. This exact native callback chain produces cosmetic visuals; the inspected path contains no outgoing damage, score, reward, or item-spawn call.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `task` | `void *` | The matching balloon task. |
| `object` | `void *` | The balloon object supplied by the native scheduler. |

## Return value

No return value.

## Usage example

```c
extern void func_08000FCC_708A0C(void *task, void *object);
typedef void (*TaskCallback)(void *, void *);

TaskCallback documented_balloon_callback(void)
{
    return func_08000FCC_708A0C;
}
```

Returns the callback address for inspection. The native scheduler owns phase progression and child creation.

## Notes

- Keep the pop branch on the naturally scheduled local balloon task and consume its phase transition once. Replaying the callback or phase increment can duplicate allocations, random-number changes, sound, and deletion.
- This finding is limited to the inspected File 48 callback chain and its identified common descendants; it does not establish that every native effect is harmless.
