`func_08001954_6F1B64` · **Function**

Runs the sweets challenge lifecycle, including local camera and player-state work, hide detection against four native positions, and phase-based bomb emission.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x08001954` | `0x006F1B64` | `.file_42` |

Native code size: **5428 bytes**.

## Signature

```c
void func_08001954_6F1B64(void *task, void *object);
```

## How it works

During a normal room 0x01E1 load, the room-specific callback preloads dynamic resource IDs 0x0020, 0x0197, 0x0159, 0x002A, 0x01E6, 0x01E1, 0x01E2, 0x01E3, 0x01CF and 0x0173 before the controller's first task callback. This callback loads resources only; it does not construct an actor. The fixed common File12 bank is separate from that preload list.

Task words +0xD0/+0xD4/+0xD8 point to the mechanism, native camera and HUD. Byte +0xDC is the phase. Signed halfwords +0xDE/+0xE0/+0xE2 hold phase frames, the spawn clock and the random threshold.

Phase 0 waits until signed frame counter +0xDE exceeds 1. With an initial zero counter, the first two callbacks wait and the third constructs the camera, HUD and mechanism. Construction sets phase +0xDC to 1 and clears +0xDE; the common epilogue leaves +0xDE at 1 and spawn clock +0xE0 at 2 on return.

The private HUD stores a signed timer at +0x80, sweets count at +0x84 and a signed displayed-heart count at +0x88. The controller initializes local maximum and current HP to 20; the displayed count is current HP minus 17, so 20 HP shows three icons and 17 HP shows none. The timer initializes to 99 seconds, represented by 2970 native frames at thirty ticks per second.

The HUD callback decrements its raw timer on each callback independently of the controller phase; controller-phase changes alone do not pause the private timer.

The native HUD timer callback reads signed raw frames at HUD task +0x80, draws signed(raw/30) seconds, then decrements the frame count once per admitted task update; normal setup starts it at 99 seconds (2970 frames). The controller's seconds getter returns zero below 30 raw frames, so its timer failure branch begins at raw < 30.

In phase 4, the controller updates its local camera and then reads the current player object directly. The native hide-center table contains these world X/Z positions:

| Center | X | Z |
| --- | ---: | ---: |
| 1 | 80 | -49 |
| 2 | 49 | 48 |
| 3 | -96 | 99 |
| 4 | -62 | -23 |

A center qualifies when native single-precision sqrt(dx*dx + dz*dz) is strictly less than 14 and player Y + 15 is strictly less than -40. No character/form, action, line-of-sight or target-pointer gate participates in this check.

On a hidden path, a warning sound is selected when the signed phase frame modulo 60 equals 2. The controller remains in phase 4 through frame 120; after that it begins a separate retraction transition. If no center qualifies, phase 4 selects animation 2 at rate 0.25 with flags 1, changes to phase 6 and resets its phase frame to 0. The ordinary epilogue advances that frame to 1; an early return after sweet allocation failure can leave it at 0.

The root creates mechanism entity 0x01AE, whose callback creates platform entity 0x01B1. It also controls robot entity 0x00FB, sweet entity 0x01AD and bomb entity 0x01AC spawning; the robot callback resides in a different native overlay.

The mechanism begins in its own phase 0, creates platform entity 0x01B1 at mechanism word +0xD0, and sets byte +0xD4 to 1. The platform separately initializes its phase byte +0xD0 to 1.

During controller phase 1, robot entity 0x00FB is requested when signed spawn clock +0xE0 modulo 201 equals 10 and the native robot count is below 2. Robot creation can therefore occur before the controller reaches its later animation phase.

Phase 1 advances when its frame counter exceeds the random threshold at +0xE2. Phase 2 reaches phase 3 when +0xDE is at least 81, selecting root animation index 0 with rate 0.125 and flags 1 through func_8021664C_5D1B1C.

The root, mechanism and platform use native task bank 0x2A; the robot uses task bank 0x20. Their model/animation resource pairs are root 0x01CF/0x0173 and robot 0x0197/0x0159; mechanism and platform model resources are 0x01E3 and 0x01E6.

Common File12 world code is loaded directly to its fixed destination by the native world loader. It need not appear in the dynamic scene-resource registry queried by func_800141C4_14DC4.

In phase 6, after checking whether the signed entry phase-frame +0xDE exceeds 120 and changing the phase back to 5 when it does, the controller still checks bomb cadence using that unchanged entry value. For example, entry frame 121 can trigger the phase change and still satisfy the residue-1 bomb request.

For a phase-6 bomb, native allocation and birth/context initialization happen before the controller consumes its two random values and stores the final X/Y/Z. A bomb position observed when allocation returns is therefore not necessarily its final placement; the controller writes the final coordinates afterward.

During phase 6, the controller requests a bomb when the entry phase-frame is 1 or 21 modulo 40. For residue 1, two native RNG calls produce X/Z offsets in [-10,9], added to the current player object's X/Z; bomb Y is 50. For residue 21, two RNG calls produce offsets in [-100,99]; X is the controller's player X clamped to [-112,112], divided by 1.2 in double precision and converted to float before adding the offset, while Z uses the current unclamped player Z plus its offset. Bomb Y is 50 in both branches.

A 120-frame pass requests six bombs; repeated phases and surviving parents can yield more than six live bombs. The bomb callback does not select a target: after its active phase waits for task status +0x68 bit 0x20 to clear, it creates two native explosion children and retires.

At current HP 17 or lower, the controller enters its failure phase. Phase 0 saves a 48-byte native player-statistics block. Phase 9 at tick 10 restores that block, runs the native exit cleanup and records the request for room 0x016D, XYZ (0,7,1), camera 0x0100, setup 0xA0 and option 0 through func_801FA420_5B6330.

Native child callback table values are mechanism 0x0800139C and platform 0x08001250 in file 0x2A, and robot 0x08001720 in file 0x20. At the parent-context inheritance stage these values can remain segmented; the recompiled scheduler resolves them before dispatch.

Returns the native callback identity. The game must supply its resident overlays, initialized controller graph and local display resources.

## Notes

- Local health and native camera/HUD pointers are distinct from shared challenge progress. Preserve each task's native initialization and cleanup.
- This scheduler-owned callback combines the local camera, phase logic, player state, statistics backup/restoration and cleanup with its position reads. Do not invoke it a second time as a hide query or swap the global player object around the whole callback.
- Child actors use the shared native actor pool. This graph has no established fixed six-bomb live limit; the common selector uses strict cap<count rejection and later allocation may still fail. Direct visual tasks can use a separate scheduler allocation path.
- The 48-byte statistics block is copied as a whole; individual field meanings are not established by this copy. The observed exit request is scoped to this native challenge lifecycle.
- A missing dynamic-registry entry for fixed File12 code does not establish that its native world functions are unavailable. Task banks and model resources have separate native loading requirements.
- The mechanism sets its initialization phase byte +0xD4 to 1 even when platform allocation returns null. The checked native path does not retry that null child at mechanism +0xD0, so the phase byte alone does not establish a complete child graph.
- A child can have its object and file ID initialized while its callback still has a raw segmented representation. For the verified 0x08000000–0x08FFFFFF callback family, compare identities using the recompiled scheduler's fixed-base mapping on a local copy, after checking file and resource residency; func_80014840_15440 applies native per-file segment mapping and does not produce the same loaded callback address. Do not advance the child's native initialization to observe its callback.
- The displayed hearts are a view of participant-local health, not a separate challenge health pool. The root saves and restores the participant’s 48-byte statistics block on the native exit path.
