`func_801EA4E8_5A63F8` · **Function**

Updates one chain link from its head endpoint and the playable owner pose without applying attacks, collision or damage.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x801EA4E8` | `0x005A63F8` | `.file_11` |

Native code size: **252 bytes**.

## Signature

```c
extern void func_801EA4E8_5A63F8(void *link, void *object);
```

## How it works

Reads the chain head through link task +0x9C and the playable owner through +0x5C. The head endpoint is the XYZ position of the head object at head task +0x18.

For owner actions 0x77 and 0x78, the player-relative hand offset is (0, 3, 11.5); other inspected chain actions use (0, 4, 14). Rotate this offset by the owner object rotations and add owner XYZ to obtain H.

Rotate (0, 0, 2.5) by the same owner rotations to obtain R. For link index i from 0 through 7, position is H + ((8 - i) / 9) * (headXYZ - H - R). The scalar division is floating point.

Head phase byte +0x60 equal to 3 hides the link through object byte +0x64. The latched phase 2 continues to display the links.

The inspected update performs position and visibility work only. It makes no function calls and does not service collision or apply damage.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `link` | `void *` | Live native link task with its playable owner at +0x5C and chain head at +0x9C. |
| `object` | `void *` | Existing display object belonging to this link. |

## Return value

No return value.

## Usage example

```c
#include "modding.h"

static float observed_link_position[3];

/* Entry reads the existing object pose before native placement updates it. */
RECOMP_HOOK("func_801EA4E8_5A63F8")
void observe_link_entry(void *link, const void *object)
{
    const unsigned char *bytes = object;
    (void)link;
    if (!bytes) return;
    observed_link_position[0] = *(const float *)(bytes + 0x08);
    observed_link_position[1] = *(const float *)(bytes + 0x0C);
    observed_link_position[2] = *(const float *)(bytes + 0x10);
}
```

This read-only entry hook copies the existing display pose before the native update computes the next link position. It retains no task or object pointers. Observing the post-update position instead requires saving and validating the intended object separately; a return hook cannot recover original arguments from caller-saved registers.

## Notes

- The update expects a fully initialized native link, head, playable owner and display object. Its lack of gameplay calls does not make arbitrary task layouts valid.
- The head and owner must remain live for every read. Do not retain link +0x9C across native teardown or task-pool reuse.
- The formula is specific to the inspected File 11 chain-pipe actors and their native scales.
