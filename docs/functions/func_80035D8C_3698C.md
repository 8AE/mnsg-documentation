`func_80035D8C_3698C` · **Function**

Pops one record from a kind-specific native free list.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80035D8C` | `0x0003698C` | `.main` |

Native code size: **112 bytes**.

## Signature

```c
extern void *func_80035D8C_3698C(short kind);
```

## How it works

Returns null when the free list is empty. Otherwise removes the head, clears its next pointer and high-bit marker, increments D_8016DAD8[kind], and returns the record.

This low-level helper does not perform an allocation-limit check or attach the record to an owner. Higher-level task allocators supply those responsibilities.

The kind-2 reset template has byte +0x65 equal to 1. Allocation does not clear that field: it clears only the high-bit marker in kind byte +0x04. Native drawing accepts nonnegative +0x65; testing equality to zero incorrectly excludes ordinary visible records.

Kind-2 records occupy 0x98 bytes and are linked CPU-side state. Skeleton cache links use +0x74 for siblings, +0x78 for children, and +0x94 for the parent; these records are separate from graphics command and matrix buffers.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `kind` | `short` | Native pool-record kind; display objects use kind 2. |

## Return value

Record pointer or null when that free list is empty.

## Usage example

```c
extern void *func_80035D8C_3698C(short kind);

/* Low-level allocator primitive only. Caller must attach the returned
 * record and release it through the native engine path. */
void *take_kind2_pool_record(void) {
    return func_80035D8C_3698C(2);
}
```

## Notes

- No capacity or kind bounds check is visible in this helper; caller must select a valid pool kind.
- A successful raw allocation must be attached/released correctly or the pool record leaks.
