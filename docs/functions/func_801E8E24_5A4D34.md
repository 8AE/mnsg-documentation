`func_801E8E24_5A4D34` · **Function**

Marks selected projectiles in the playable player's owned task subtree for deferred removal.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x801E8E24` | `0x005A4D34` | `.file_11` |

Native code size: **104 bytes**.

## Signature

```c
extern void func_801E8E24_5A4D34(void *player, unsigned char reason);
```

## How it works

Reads the owned-projectile manager through player task +0xDC, follows its task links, and examines tasks while their priority exceeds the playable player's priority.

Uses each child's type byte at +0x64 to select the native cancellation table. Eligible entries are marked with byte +0x65 = 1 and byte +0x66 = reason; this table has no entries for kinds 0x17 through 0x1B.

The owned-projectile manager processes these marks during its ordinary updates. The normal damage caller supplies reason 1 after a nonzero intake result.

The owned-projectile manager walks its child tasks on each update. For a child with nonzero +0x65, it decrements +0x66 and removes the child when the prior +0x66 value was zero. A mark of +0x65 = 1 and +0x66 = 0 therefore requests removal on the next manager pass.

Native projectile construction initializes removal bytes +0x65 and +0x66 to zero and stores the projectile kind at +0x64.

## Usage example

```c
#include "modding.h"

static unsigned char last_projectile_cancel_reason;

RECOMP_HOOK("func_801E8E24_5A4D34")
void observe_projectile_cancellation(void *player, unsigned char reason)
{
    (void)player;
    last_projectile_cancel_reason = reason;
}
```

The example illustrates the native interface and its required state.

## Notes

- The player and its +0xDC manager must be live and initialized; the native function does not perform these pointer checks.
- The cancellation routine marks only kinds present in its table; kinds 0x17 through 0x1B are skipped there. The manager still honors removal marks placed directly on a child, regardless of kind.
