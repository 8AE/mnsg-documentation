## How it works

Common bomb update body. The three variant callbacks provide its initial player-relative spawn offset; phase zero rotates a local launch vector into world space, initializes the attack descriptor and starts a 90-tick flight.

At launch, the native variants use a player-relative offset of (0, 125.3, 75.13). The update reads three owner-task floats at +0x68/+0x6C/+0x70, adds 5 to the Y component and 3 to Z, rotates the local vector using the owner display object angles at +0x14/+0x16/+0x18, then stores world velocity in bomb task +0x6C/+0x70/+0x74.

Each flight update applies gravity of approximately -2/3 to vertical velocity, advances the bomb and tests collision. On collision, the phase machine enters its impact behavior, creates the impact model and fades it before requesting task removal through byte +0x65.

The outgoing attack descriptor has bit 2 set at +0x30, -1 at +0x48, 0x1C at +0x4C and 30 at +0x4E; the impact descriptor writes 100 at +0x4E. These are observed field values; the inspected trace does not establish every field's semantic meaning.

Phase zero also consumes ammunition and sets a 90-tick halfword lifetime at +0x62 before advancing to phase one. A phase-zero entry becomes a usable initial flight pose only after initialization returns in phase one. Calling this update on a display-only task would mutate ammunition and native attack state.

## Return value

No return value.

## Usage example

```c
#include "modding.h"

static void *updating_task;
static unsigned char observed_phase;

RECOMP_HOOK("func_801EBF48_5A7E58")
void observe_update_entry(void *task)
{
    updating_task = task;
}

RECOMP_HOOK_RETURN("func_801EBF48_5A7E58")
void observe_update_return(void)
{
    if (updating_task)
        observed_phase = ((const unsigned char *)updating_task)[0x60];
    updating_task = 0;
}
```

Read-only entry/return observation of the existing native update. Save the task argument at entry: a return hook cannot assume that the original argument registers survived the native call. Native task validity and ownership must still be checked before any subsequent operation.

## Notes

- The routine updates an existing native actor and its complete work state. Do not call it as a generic spawner or use it on a display-only task.
- The native manager processes removal requests after the update. Do not retain task or object addresses across destruction or storage reuse without checking their lifecycle.
- The common update is reached through native variant callbacks. Preserve every native argument if directly calling the function; an observation hook may read only the first argument.
