`func_80033404_34004` · **Function**

Tests the sphere decoded by the attack-group scanner against eligible victim tasks.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80033404` | `0x00034004` | `.main` |

## Signature


## How it works

At entry, four float scratch globals hold the current attacker-local X/Y/Z/radius. func_80033024_33C24 initializes them for both animated melee volumes and fixed projectile volumes.

The overlap path scales the offsets by object +0x1C/+0x20/+0x24, rotates them with func_80033898_34498 using the masked 10-bit rotations at +0x14/+0x16/+0x18, and adds world position at +0x08/+0x0C/+0x10. Attack radius is multiplied by object scale X.

Victim eligibility requires an appropriate incoming collision flag, a distinct kind-2 render object, no existing task +0x38 incoming hit, and nonzero body radius at +0x3C. Ordinary incoming bit 0x01 and special filtered incoming bit 0x04 are separate paths.

An overlap writes the victim task pointer to attacker +0x34, the attacker pointer to victim +0x38, and the current one-based sphere index to victim byte +0x44. The scan stops once attacker +0x34 is nonzero. This function does not itself subtract health.

The native body test uses radius at task +0x3C times object scale X and height at +0x3E times scale Y. For nonzero height it expands the X/Z radius by the attack sphere radius and checks the sphere against the body Y interval.

## Notes

- The scratch sphere belongs to the current scan only. Copy it at entry; do not retain its contents as a later frame or another attacker state.
- Adding arbitrary tasks to native victim lists consumes hit records and can alter projectile or enemy callbacks. A read-only observer should leave task +0x34/+0x38 untouched.
- The victim pointer must be a live initialized list; its priority is read before a null check.
- Radius zero should not be promoted to a damaging body-proximity event by an observer. Health, invulnerability, ownership and hit deduplication remain separate concerns.
