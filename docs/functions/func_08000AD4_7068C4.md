`func_08000AD4_7068C4` · **Function**

Initializes seventeen native collision platforms, runs instruction and gameplay-music transitions, and creates the challenge HUD before active play.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x08000AD4` | `0x007068C4` | `.file_47` |

Native code size: **4020 bytes**.

## Signature

```c
void func_08000AD4_7068C4(void *task, void *object);
```

## How it works

Task byte +0xD0 is the controller phase. Initialization phase 0 creates seventeen platforms; phase 1 is reached only after the complete graph exists. An initialization failure selects inert phase 4.

Task byte +0xD1 selects the camera; +0xD2 is the warning state. Halfwords +0xD4, +0xD6 and +0xD8 hold the frame counter, repeat state and previous input. Words +0xDC and +0xE0 are local display handles; +0xE4 is the HUD task pointer.

Phase 1 starts scenario 0x0179 at frame 6 and then selects phase 2. The scenario supplies instruction dialogue, waits and audio commands; it does not construct platforms.

Scenario 0x0179 queues native audio command 0x0292 before its final instruction text and wait. After setting instruction flag 0x21, it queues gameplay music command 0x0052 through func_80038BC8_397C8 and ends.

Phase 2 creates the local HUD, initializes its displayed timer to 99 (raw 3960), clears the native instruction-state byte, and advances to phase 3.

Phase 2 waits for the native instruction VM to become inactive. Its HUD transition contains no music call, so continuing past scenario 0x0179 also bypasses that scenario's gameplay-music command.

| Parameter | Type | Description |
| --- | --- | --- |
| `task` | `void *` | Live task initialized by the matching native constructor. |
| `object` | `void *` | The task's own native render or collision object, where this callback uses one. |

## Return value

No return value.

## Usage example

```c
extern void func_08000AD4_7068C4(void *task, void *object);

typedef void (*NativeTaskCallback)(void *, void *);

/* Observe callback identity; the native scheduler owns execution. */
NativeTaskCallback documented_callback(void)
{
    return func_08000AD4_7068C4;
}
```

This returns the callback address without executing initialization, moving a platform, or advancing the challenge. The callback requires the matching resident overlay and initialized native task graph.

## Notes

- A phase change alone cannot recreate platform initialization. A continuation past the introduction requires all seventeen native platform initializers to have completed and the instruction VM to be inactive.
- Camera state, display handles and task pointers belong to the local native graph. Copying raw pointers into another graph is not established as safe.
- A continuation that skips the instruction scenario must account for its local audio transition separately. Queue the gameplay command once at the intended active-play transition; repeated frame-by-frame submission is not prevented by a persistent already-playing check.
