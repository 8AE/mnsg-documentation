`func_80215CA4_5D1174` · **Function**

Initializes, opens and fades the native in-game room minimap.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80215CA4` | `0x005D1174` | `.file_12` |

Native code size: **1240 bytes**.

## Signature

```c
extern void func_80215CA4_5D1174(void *task, void *object);
```

## How it works

The file_0D callback uses task +0xDC as a 32-bit state: zero initializes, one is hidden, two is open and three fades out.

Initialization reads origin X/Y from object floats +0x08/+0x0C and world extent from object u16 +0x14. These become system +0x3B000/+0x3B004/+0x3B008. Room 0x0132 overrides extent with 6900.

Initialization releases the task's old display records and appends compass, local marker and map background as kind-1 records. Task +0xE0 points to the local marker, +0xE8 to the compass; +0xE4 is a 32-bit shape selector (zero rectangular, nonzero square).

In states two and three it calls func_80216228_5D16F8 for the local marker. It obtains the map background by following the first link of that marker, so inserting between them breaks native fading.

The map background and compass fade between alpha zero and 160. The local marker blinks independently. Sprite alpha is byte +0x10; screen coordinates are signed shorts +0x1C/+0x20.

All attached records belong to the native task. Additional records may be appended after the background without changing the local-to-background link.

## Usage example

```c
#include "modding.h"

static int minimap_state;
RECOMP_HOOK("func_80215CA4_5D1174")
void observe_minimap(unsigned char *task, void *object)
{
    minimap_state = *(int *)(task + 0xDC);
}
```

The example illustrates the native interface and its required state.

## Notes

- Only access this layout while its owning overlay and task are active. Task-pool addresses can be reused after destruction.
- State zero may invalidate every previously retained display pointer. An allocation failure can destroy the task before initialization finishes.
