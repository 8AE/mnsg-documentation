`func_800144E8_150E8` · **Function**

Loads a resource into scratch memory, decodes PIC image data or copies raw bytes into a caller-provided output buffer, and returns the output end pointer.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x800144E8` | `0x000150E8` | `.main` |

Native code size: **204 bytes**.

## Signature

```c
extern unsigned char *func_800144E8_150E8(unsigned int resource_id, void *packed_scratch, void *decoded_out);
```

## How it works

Calls func_800145B4_151B4 to load the selected resource into packed_scratch. If the loaded data begins with the ASCII bytes PIC, it parses the picture header and decodes pixels into decoded_out; otherwise it copies the loaded byte range unchanged into decoded_out.

For PIC input, the return advances by the decoded byte count from the parsed metadata. For non-PIC input, it advances by the loaded byte count. The routine writes back the output data cache before returning.

Loading and decoding are synchronous. The resource tables and PI manager must already be initialized, and callers should perform this work at a resource-initialization boundary rather than once per frame.

The [native texture gallery](/textures/) records verified US image resources, ROM addresses, decoded sheets, and item crops. For example, resource 0x800E at ROM 0x007E9570 decodes to a 64x32 RGBA5551 sheet containing the silver and gold fortune dolls in adjacent 24x24 cells at (0,0) and (24,0). The four face cells in resource 0x868C must be flipped vertically to match the native map-marker quads.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `resource_id` | `unsigned int` | General-file or packed-resource ID accepted by the underlying resource loader. |
| `packed_scratch` | `void *` | Caller-owned, DMA-aligned writable scratch buffer large enough for the loaded representation. |
| `decoded_out` | `void *` | Caller-owned writable destination large enough for the raw copy or decoded picture data. |

## Return value

Pointer one byte past the output written to decoded_out. If the loader produces no bytes, returns decoded_out unchanged.

## Usage example

```c
extern int func_80014698_15298(unsigned int resource_id, void *rom_address_out);
extern unsigned char *func_800144E8_150E8(unsigned int resource_id,
                                          void *packed_scratch,
                                          void *decoded_out);

enum {
    PICTURE_RESOURCE_ID = 0x8016u,
    PICTURE_ROM_ADDRESS = 0x007EB740u,
    PICTURE_STORED_BYTES = 0x02C0u,
    PICTURE_DECODED_BYTES = 0x1000u
};

static unsigned char packed[PICTURE_STORED_BYTES] __attribute__((aligned(16)));
static unsigned char decoded[PICTURE_DECODED_BYTES] __attribute__((aligned(16)));

unsigned char *load_known_picture(void)
{
    unsigned int rom_address = 0;
    unsigned char *end;

    if (func_80014698_15298(PICTURE_RESOURCE_ID, &rom_address) !=
            PICTURE_STORED_BYTES ||
        rom_address != PICTURE_ROM_ADDRESS)
        return 0;

    end = func_800144E8_150E8(PICTURE_RESOURCE_ID, packed, decoded);
    return end == decoded + PICTURE_DECODED_BYTES ? decoded : 0;
}
```

This example uses a verified resource whose ROM address, stored size, and decoded size are known in advance. Those checks are part of the asset contract.

## Notes

- Neither destination has a capacity argument. Establish both the stored size and the maximum decoded size for the exact resource before calling; checking the returned pointer afterward cannot prevent an overrun.
- Use separate, nonoverlapping packed and decoded buffers. The picture decoder resets and mutates resident global workspace, so serialize this function with other picture decodes on the game thread.
- The packed destination must satisfy the PI DMA alignment requirements. If decoded bytes will be referenced by native display-list or segmented texture commands, keep them in original 8 MiB RDRAM and retain them for the renderer's full lifetime.
