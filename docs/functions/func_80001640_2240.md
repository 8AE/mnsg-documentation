`func_80001640_2240` · **Function**

Copies a ROM byte range to memory and waits for DMA completion.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80001640` | `0x00002240` | `.main` |

Native code size: **164 bytes**.

## Signature

```c
extern void func_80001640_2240(unsigned int rom_addr, void *dst, unsigned int size);
```

## How it works

Invalidates destination data and instruction caches, starts a PI DMA read from ROM, blocks on its completion message, then returns. The function itself does not read the separate loader-mode byte.

The example preserves the surrounding loader-mode convention at address 0x8015C5D4 while copying raw action data. Decompression, destination allocation and scene registration are separate operations.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `rom_addr` | `unsigned int` | ROM source address. |
| `dst` | `void *` | Writable destination with sufficient capacity. |
| `size` | `unsigned int` | Number of bytes to copy. |

## Return value

No return value.

## Usage example

```c
extern void func_80001640_2240(unsigned int rom_addr, void *dst, unsigned int size);

void copy_raw_rom_range(unsigned int start, unsigned int end, void *dst) {
    if (!dst || end <= start) return;
    volatile unsigned char *mode =
        (volatile unsigned char *)0x8015C5D4;
    unsigned char previous = *mode;
    *mode = 1;
    func_80001640_2240(start, dst, end - start);
    *mode = previous;
}
```

## Notes

- The destination must already have capacity for the complete byte range and meet the DMA path alignment requirements.
- This copies raw bytes; it does not by itself decompress or register the resource.
