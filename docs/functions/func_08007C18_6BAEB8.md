## How it works

The active spinning callback func_08007BB0_6BAE50 installs this state at yaw 0x360 with an unsigned-halfword timer of 60 at task +0x8A.

Decrements the timer first. On every call with a remaining value at most 30, sets bit 0x80 in the parent root word at task +0xE8. A remaining value of zero also schedules the next native callback.

Growing ray children observe parent bit 0x80 and select func_080009C4_6B3C64 for their next AI pass. That fade callback clears the shared parent bit, so it can be absent again after the scheduler finishes.

The stop bit is a consumed signal rather than a persistent ray-lifetime flag. The root callback and countdown identify the wind-down even after a child clears the signal.

## Notes

- A post-scheduler sample of parent +0xE8 can miss a stop signal already consumed by ray children. Do not infer that existing rays should still grow solely from a clear bit 0x80.
- Changing the parent signal does not reset a ray fade that already began. Its unsigned-byte color/opacity scalar at task +0xEC continues toward removal.
- Resolve the full ROM-qualified overlay symbol; a shared 0x080... address alone does not identify the loaded routine.
- Use a live task of the documented family. Task pointers and callback slots follow the 32-bit target ABI.
