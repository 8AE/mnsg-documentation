`func_08005018_6C4768` · **Function**

Initializes Congo’s Miracle Moon reward when its pickup scene is not complete.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x08005018` | `0x006C4768` | `.file_30` |

Native code size: **120 bytes**.

## Interface

A complete callable prototype has not been established. Use the observation or callback-identity pattern in the example rather than guessing the native arguments.

## How it works

The room 0x0016 reward is placed as entity 0x35F and uses file_30. This initializer assigns native entity identity 0x350 at task +0x5E.

Saved flag 0x0A4 suppresses reward setup when the Moon pickup scene has already finished. Inventory ownership at save +0x254 is a separate value and is not this completion test.

The next callback waits for Congo victory flag 0x12B before the reward appears and enters its idle pickup behavior.

## Usage example

```c
#include "modding.h"

extern void *D_8016DAB4_16E6B4;
static unsigned int initialized_moon_rewards;

RECOMP_HOOK_RETURN("func_08005018_6C4768")
void observe_moon_initialization(void)
{
    /* The scheduler still owns the current task at constructor return. */
    const unsigned char *task = D_8016DAB4_16E6B4;
    if (!task || *(const unsigned short *)(task + 0x5E) != 0x350u ||
        (*(const unsigned int *)(task + 0x68) & 2u)) return;
    ++initialized_moon_rewards;
}
```

Observe only a successfully initialized native reward at constructor return. Read the scheduler current-task value in this callback context rather than assuming the first argument register survived initialization.

## Notes

- Requires the native room placement and file_30 resources; this is not a general collectible constructor.
- Do not infer pickup completion from the inventory word alone.
- An observation hook is shown; no direct constructor call is required.
