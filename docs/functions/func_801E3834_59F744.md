`func_801E3834_59F744` · **Function**

Arms the real playable task with an attack descriptor and native kind chosen from the character, weapon selection and attack variant.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x801E3834` | `0x0059F744` | `.file_11` |

Native code size: **652 bytes**.

## Signature

```c
extern void func_801E3834_59F744(void *player, unsigned char attack_variant);
```

## How it works

Writes the outgoing attack descriptor at task +0x48 and the unsigned native attack-kind byte at +0x4C. The character index is the unsigned byte at task +0x60: 0 Goemon, 1 Ebisumaru, 2 Sasuke, 3 Yae.

For the ordinary tiered weapon, Goemon and Ebisumaru use kinds 0x15, 0x16 and 0x17 at tiers zero, one and two. Sasuke and Yae use 0x19, 0x23 and 0x24.

For selected weapon 2, the kind table by character index is [0x15, 0x1D, 0x1C, 0x15]. Ebisumaru therefore arms the Meat Hammer with kind 0x1D.

For selected weapon 3, the kind table by character index is [0x15, 0x14, 0x1A, 0x15]. Ebisumaru therefore arms the Wind-up Camera with kind 0x14.

An already armed attack is identified by the task kind, rather than merely by the current selected weapon. For an active native outgoing sphere, the real playable task with character 1 and kind 0x1D identifies an Ebisumaru Meat Hammer strike. A child projectile or a display-only task does not become that playable attack because it shares a kind value.

The native variant tables contain 20 entries, indexed 0 through 0x13, without a bounds check. The inspected Meat Hammer setup contexts pass variants 0x0F, 0x12 and 0x13. The initializer also performs per-variant native setup and may request an effect; it is not a descriptor-only or visual-only setter.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `player` | `void *` | Live real playable task with character byte +0x60, initialized private work at +0x5C and its native resource context. |
| `attack_variant` | `unsigned char` | Native attack/animation variant index into character-specific 20-entry tables. This is not the selected-weapon value. |

## Return value

No return value.

## Usage example

```c
#include "modding.h"

static unsigned char observed_attack_variant;
static unsigned char observed_character;

RECOMP_HOOK("func_801E3834_59F744")
void observe_attack_setup(void *player, unsigned char attack_variant)
{
    const unsigned char *task = player;
    if (!task) return;
    observed_attack_variant = attack_variant;
    observed_character = task[0x60];
}
```

Observe an existing native call without changing its arguments or replaying attack initialization. This entry hook sees the supplied variant before the original initializer arms the descriptor and kind.

## Notes

- Only use the callable interface in the matching native playable action, with complete task, work and loaded-resource state. A valid variant range alone does not establish that the variant is appropriate for a particular character or action.
- The initializer mutates outgoing gameplay collision state. Do not invoke it on a visual-only task or to replay another player’s attack.
- The variant parameter is byte-sized; preserve its unsigned width. Do not substitute the 32-bit weapon selection word or a weapon-acquisition flag.
