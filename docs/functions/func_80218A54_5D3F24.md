## How it works

Resolves instance->definition through the active actor-data file, sets actor/entity IDs at task +0x5C/+0x5E, copies the signed 16-bit spawn transform into the model and copies definition words into task +0xD0/+0xD4/+0xD8.

Assigns an incrementing 8-bit generation at +0x74, initializes actor state and installs the native earlier callback FUN_8021925C and common post func_80218F30_5D4400.

D_8015CDDC identifies the current room instance and D_8015CDE0 holds the current resolved definition during the native spawn path. These are transient scratch pointers.

Resolves instance->definition using the active actor-data file, updates D_8015CDE0, copies actor ID into +0x5C/+0x5E and applies the instance transform to the task display object.

Copies definition payload into +0xD0/+0xD4/+0xD8, initializes actor state, and installs native update/finalizer callbacks. It requires a valid allocated display object and resident actor-data resources.

Calling this initializer from a hook on itself requires a recursion guard. The shared definition pointer can change during nested initialization.

## Notes

- The active actor-data file must be loaded before resolving the definition.
- Entry occurs before task initialization. Inspect final identity fields only after the native routine completes.
- Requires a valid allocated actor with a display object and resident actor-data wave. Native segmented definition resolution can fault when resources are absent.
- Its global definition context changes during initialization. Do not retain it as a per-enemy stable pointer without validating the scene.
- Calling from its own hook requires a recursion guard. The example assumes duplicate and duplicate_instance were prepared by the recovered call pattern spawning pattern.
