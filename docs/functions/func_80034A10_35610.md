`func_80034A10_35610` · **Function**

Clears native task linkage, callback, object, contact and common work fields before storage is reused.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80034A10` | `0x00035610` | `.main` |

Native code size: **168 bytes**.

## Signature

```c
extern void *func_80034A10_35610(void *task);
```

## How it works

Receives a task-storage pointer and returns the same pointer. Clears links at +0x00/+0x04, callbacks, primary and secondary object pointers, contact state and the common task work range.

The native allocator at 0x80034B58 calls this resetter after taking a task from the free pool and before writing its new linkage, priority and callback.

An entry hook can discard cached external identities associated with the task address before the new task lifetime begins. Address equality alone cannot distinguish old and newly allocated tasks.

## Return value

The input task pointer.

## Usage example

```c
#include "modding.h"

static void *observed_task;

RECOMP_HOOK("func_80034A10_35610")
void forget_reset_task(void *task)
{
    if (observed_task == task) observed_task = 0;
}
```

The hook invalidates a caller-owned cached identity and leaves native reset/allocation behavior untouched.

## Notes

- This is a storage resetter, not a safe destructor for a linked task. Calling it directly on a live actor erases pointers without performing its complete destruction lifecycle.
- At an entry hook, fields still belong to the preceding storage state; they do not describe the new object that the allocator has not constructed yet.
- The same task and object addresses can be reused within one frame. Use lifecycle observation when assigning a durable external identity.
