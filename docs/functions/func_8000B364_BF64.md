`func_8000B364_BF64` · **Function**

Prepares loading of the configured destination scene.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x8000B364` | `0x0000BF64` | `.main` |

Native code size: **128 bytes**.

## Interface

A complete callable prototype has not been established. Use the observation or callback-identity pattern in the example rather than guessing the native arguments.

## How it works

Consumes the prepared destination stage, preserves the previous current room at full-system +0x3ADFC, and writes the new current room at +0x3ADF2. It calculates region/substage, begins scene-load bookkeeping and resets transition counters.

The ordinary main-step-12 handler invokes this function after its transition wait has completed, then resets rendering and switches to main step 13. This route uses the prepared destination and does not read the saved respawn transform.

Save-file loading has a distinct spawn-reading route. Do not require saved respawn fields to match every live warp; do not assign the current room early to bypass native scene preparation.

## Return value

No return value in the established declaration.

## Usage example

```c
#include "modding.h"
extern unsigned short D_800C7AB2;

static unsigned short s_last_prepared_room;

RECOMP_HOOK_RETURN("func_8000B364_BF64")
void observe_prepared_scene(void)
{
    /* The native consumer has assigned the current room at this boundary. */
    s_last_prepared_room = D_800C7AB2;
}
```

The return hook observes the room after native destination consumption without manually replaying individual scene-load steps. Player and stage resources may still be loading.

## Notes

- Changing only current room or calling this with stale destination fields can load inconsistent state.
