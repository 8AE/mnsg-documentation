## How it works

The encounter is multipart. The battle child is distinct from camera, scene and encounter controllers that can share actor/entity family 0x1B0.

The flight encounter creates this as a distinct kind-6 child with func_802171A8(root, func_08002D18_703E18, 6) and writes the root pointer to child +0xD0. Its initializer runs on a later scheduler pass, then sets entity halfword +0x5E to 0x1B0 and HP byte +0x8D to 5.

Task +0x04 is a mutable pointer-to-pointer backlink and is not a stable parent pointer; use the initializer's explicit child +0xD0 root link when identifying this child.

The later pre-fight proximity state is func_08002EB4_703FB4; when the absolute Z separation between player and child objects is below 200.0, it schedules the first combat callback func_08002F58_704058.

At zero HP, the death state func_08002540_703640 schedules func_080031D8_7042D8. Later callbacks advance through func_08003634_704734, func_08003678_704778 and func_080036CC_7047CC, where the child is deleted.
