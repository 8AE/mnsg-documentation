`func_8000607C_6C7C` · **Function**

Writes pending destination room, XYZ, base player heading, packed camera-start parameter and related loading fields.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x8000607C` | `0x00006C7C` | `.main` |

Native code size: **88 bytes**.

## Signature

```c
extern void func_8000607C_6C7C(unsigned short room, short x, short y, short z,
                              short base_heading, short packed_camera_start,
                              short script_resource, unsigned int script_address);
```

## How it works

Writes the destination room at full-system +0x3AFE0, packed camera-start parameter at +0x3AFE2, X/Y/Z at +0x3AFE4/+0x3AFE6/+0x3AFE8 and base player heading at +0x3AFEA. It sets destination-transition byte +0x3AE29 to 1 and stores the script resource ID and script address at +0x3AE3A and +0x3AE3C.

This prepares a destination without assigning the current room. In ordinary live File11 gameplay, func_801F77F4_5B3704 observes the request marker and selects native room teardown and reload. The separate full main-system step-12 route also consumes pending fields, tears down the world and enters step 13; these lifecycles are not interchangeable.

The live step-12 route consumes the prepared destination directly; it does not read the saved respawn transform. Save-file loading has a separate spawn-reading route. Preserve saved respawn fields when requesting an ordinary live warp unless changing the saved return point is also intended.

This setter leaves the extended setup word at +0x3AE2C and option halfword at +0x3AE30 untouched. Native camera initialization can use a nonzero setup word to override the ordinary arrival transform even when transition-marker bit 0x08 is clear.

The sixth argument is the native packed camera-start parameter. File11 initialization stores its low byte at camera-task +0xBC; startup uses byte >> 3 as an unguarded index into five callbacks and direction bits for camera facing. Passing an arbitrary rotation here can select an invalid callback.

A newly assigned room ID also needs bounded graphics/group indices, a valid default-start reader and installed room actor metadata before native rebuild consumers run. Queuing explicit coordinates does not bypass those independent reads.

The seventh and eighth arguments are a signed 16-bit script resource ID and a 32-bit segmented script address. The native script-start consumer loads a nonzero resource through the scene registry, maps the script and starts it. Zero for both requests no queued native script. Resource -1 belongs to separate menu/demo behavior, not controller selection.

The ordinary hot transition retains the live player task, its controller byte at +0x90 and character byte at +0x60 while replacing room task subtrees. The final two arguments do not select the controller or character. Cold player allocation has a separate controller-zero initialization policy.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `room` | `unsigned short` | Destination room/stage identifier. |
| `x, y, z` | `short` | Destination player coordinates. |
| `base_heading, packed_camera_start` | `short` | Base player Y heading in native 10-bit phase (1024 units per revolution), also used as a camera baseline; separate packed camera-start parameter selecting startup callback group and direction. |
| `script_resource` | `short` | Signed 16-bit queued native script resource ID. Zero means no queued script; -1 has separate menu/demo semantics. |
| `script_address` | `unsigned int` | 32-bit segmented address of the queued native script. Ordinary requests pass zero with script_resource zero. |

## Return value

No return value.

## Usage example

```c
extern short D_8006B780_6C380[];
extern void func_8000607C_6C7C(unsigned short room, short x, short y, short z,
                              short base_heading, short packed_camera_start,
                              short script_resource, unsigned int script_address);

/* Call only from a loaded ordinary world after all native dialogs, pause,
 * scripted movement and an existing transition have finished. */
void queue_congo_destination(void)
{
    const unsigned short room = 0x0016;
    const short *start = &D_8006B780_6C380[room * 5u];
    func_8000607C_6C7C(room, start[0], start[1], start[2],
                     start[3], start[4], 0, 0);
}
```

Queues the verified Congo arrival fields and no native script during ordinary live File11 gameplay. The existing scene callback owns the hot transition and retains the player task, selected controller and character. This example does not alter saved respawn state or force a full system-step rebuild.

## Notes

- This queues destination state; it does not alone execute a complete warp.
- Do not request a second warp while a native transition, pause, conversation or scripted movement owns the player. A loaded save and a live ordinary-world player are prerequisites for this call sequence.
- This basic destination setter and the extended native room-request helper write different fields. Preserve the surrounding native camera/setup lifecycle rather than treating the request helpers as interchangeable.
- Passing zero for script_resource and script_address does not clear the separate extended setup and option fields. Establish the target camera lifecycle's required values before requesting a rebuild.
- The camera-start byte and base heading have different units and roles. Use validated native startup values; an in-range callback index alone is not a complete camera-lifecycle guarantee.
