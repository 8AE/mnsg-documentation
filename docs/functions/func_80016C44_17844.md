`func_80016C44_17844` · **Function**

Applies object visibility and render context before dispatching model drawing.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80016C44` | `0x00017844` | `.main` |

Native code size: **2732 bytes**.

## Signature

```c
extern int func_80016C44_17844(void *object);
```

## How it works

Rejects an object when byte +0x64 has bit 0 set, signed byte +0x65 is negative, or the native visibility/culling checks reject it. A nonnegative +0x65, including the reset-template value 1, is accepted by this gate.

Binds the current object through D_801684A0 and dispatches the model command at +0x2C using the material/context word at +0x30 and segment bases beginning at +0x34.

For case-6 model commands whose low bit is zero, sets transform-mode byte D_8016852D to 1. Only this dispatcher writes that mode byte in the inspected executable. The nested skeleton traversal does not recursively call this dispatcher.

A case-6 header with bit 31 set reaches the cached model tree through its root pointer at header +0x08. Signed relative node indices at +0x04 and +0x05 use 24-byte nodes.

The native renderer advances command and matrix cursors without capacity checks. CPU model-cache capacity, final graphics-bank storage, and the 16-entry temporary transform stack are separate constraints.

## Return value

Zero when visibility or native culling rejects the object; one when the native object path is processed. This is not proof that a GPU submission has completed.

## Usage example

```c
extern int func_80016C44_17844(void *object);

#include "modding.h"

RECOMP_HOOK("func_80016C44_17844")

    (void)object;
    /* Observe only; the caller owns the active rendering lifecycle. */
}
```

The example illustrates the native interface and its required state.

## Notes

- object must be a valid native display record with resident model and segment resources. Calling this from arbitrary gameplay code does not establish render context.
- A general model or inline material list can require an unbounded number of commands. Any preflight bound must constrain the accepted model/material path and validate tree offsets, cycles and depth.
