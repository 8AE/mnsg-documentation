`func_80036158_36D58` · **Function**

Unlinks and cleans a count of consecutive render records from their owning native task.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80036158` | `0x00036D58` | `.main` |

Native code size: **264 bytes**.

## Signature

```c
void *func_80036158_36D58(void *task, void *first, unsigned char count);
```

## How it works

Finds the supplied first record in the native task attachment chain, unlinks the requested consecutive records and repairs the owner head and tail pointers.

Runs native render-record cleanup, including internal model-cache cleanup, before returning each removed record to its native pool.

The count parameter uses only the low unsigned 8 bits of the argument. The returned pointer identifies the surviving successor; it is not a removed record or a new allocation.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `task` | `void *` | Live native task that still owns the attached record chain. |
| `first` | `void *` | First still-owned record in the task chain to remove. |
| `count` | `unsigned char` | Unsigned 8-bit number of consecutive records to remove. Use 1 for one known owned record. |

## Return value

First surviving successor after the removed records, or null when no successor remains.

## Usage example

```c
extern void *func_80036158_36D58(void *task, void *first, unsigned char count);

/* Both pointers must already be validated as live and still linked. */
void *remove_one_owned_record(void *task, void *record)
{
    if (!task || !record) return 0;
    return func_80036158_36D58(task, record, 1);
}
```

Removes one known owned attachment through native cleanup rather than manually repairing list links or retaining a freed object.

## Notes

- Validate that the task is still live and that first is still a member of its attachment chain before calling. A retained pointer may have been freed or reused after native task cleanup.
- Do not remove unrelated original HUD records or free the same attachment again after the owning task has already released its chain.
- The single-record example assumes ownership has already been established; non-null checks alone do not prove that precondition.
