## How it works

Calls FUN_80218E7C, clears task fields +0x34/+0x38 and tests removal-pending bit 0x02 in status +0x68.

Pending removal deletes the current task and updates or schedules bookkeeping associated with the room-instance pointer at +0x70.

Ordinary room actors install this callback at task +0x10. Some multipart bosses use private post routines: Congo, Dharumanyo and Tsurami have additional actor-specific processing.

Invokes the common actor updater, clears actor+0x34/+0x38 references, then tests status bit 0x2 at +0x68. A pending removal enters native task cleanup and related room-instance bookkeeping.

A targeted entry hook can mark a validated actor before the removal check. The original routine must retain ownership of cleanup. On return the actor may already have been removed.

## Notes

- The routine may delete its task. An entry-captured pointer can be invalid on return.
- Repeating the callback can repeat movement, collision and lifecycle work.
- A save bit alone does not refresh an existing collectible actor.
- Do not apply this pattern to Miracle items or bosses: they require their own cutscene/defeat lifecycles.
- An actor can be freed by this routine; a return hook must not blindly dereference the old pointer.
