`func_80013B14_14714` · **Function**

Loads a file into the scene resource registry and advances its aligned allocation boundary.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80013B14` | `0x00014714` | `.main` |

Native code size: **248 bytes**.

## Signature

```c
extern void *func_80013B14_14714(unsigned int file_id);
```

## How it works

Searches existing file IDs or claims the next zero-ID registry entry. Loading uses FUN_80001C00 and registration uses FUN_800142BC. Some file types first align their load address to 0x1000; the next boundary is aligned to 0x40.

The result is the next allocation boundary, not the loaded resource base. For an existing file, the routine returns the following entry data pointer. Call func_800141C4_14DC4 afterward to obtain the file base.

Searches for an existing file or the first zero-file sentinel. For a new file, it loads the data, registers its segment metadata, then writes a following zero-file sentinel containing the next 64-byte-aligned destination. Certain files additionally require 4096-byte alignment and a cached-address tag.

Its return is the next arena cursor, not the loaded file base. Retrieve the registered base with func_800141C4_14DC4 after loading.

## Parameters

| Parameter | Type | Description |

| `file_id` | `unsigned int` | File identifier. The native routine consumes a 16-bit ID; the documented call uses an unsigned word argument. |

## Return value

Aligned next allocation boundary, or null if the registry scan cannot allocate an entry. It is not the resource base.

## Notes

- Use the native scene-resource lifecycle and available memory budget when requesting files.
- Do not treat the return value as a model or file-data pointer.
- The return is the next arena cursor / next registry entry data, not the loaded file base.
- Only use a valid file ID during a scene-loading phase, with registry and arena capacity available.
- Scene-resident pointers must be reacquired after a stage change.
