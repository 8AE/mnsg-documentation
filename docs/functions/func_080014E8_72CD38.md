`func_080014E8_72CD38` · **Function**

Runs the sign interaction, local camera and swimming setup, 50-second countdown, obstacle spawning, result cleanup, and Mermaid reward dialogue at the Waterfall of Kegon.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x080014E8` | `0x0072CD38` | `.file_69` |

Native code size: **4264 bytes**.

## Signature

```c
void func_080014E8_72CD38(void *task, void *object);
```

## How it works

This File 69 controller runs in room 0x0154. Merely entering that room does not start the trial. In phase 3, after the native scenario becomes idle, the controller accepts the normal start exactly when story flag 0x0015 is set, interim success flag 0x001E is clear, selected character is 3 (Yae), and accepted-dialogue-choice flag 0x007A is set. Acceptance changes phase 3 to phase 4; rejection selects phase 12. This block does not read the Mermaid ability counter at save +0xF0 or permanent reward flag 0x001F.

Before dispatching any phase, the native controller reads the unsigned 16-bit held-button field at full system +0x3B092. This is the second native controller's held state. When Start mask 0x1000 is held there, the routine sets story flag 0x0015, including while the sign is idle or the controller is initializing. This native input path does not require a sign conversation.

Initialization phase 0 changes task halfword +0x5E from its birth entity 0x033A to 0x0327, configures the sign, and ends in phase 1. The initialized controller cannot be identified by requiring its old +0x5E value.

Scenario 0x0176 clears flag 0x007A before selecting its dialogue branch. That flag records a transient accepted choice, rather than persistent permission to join a trial. Failure flag 0x001D is a retry outcome; the phase-3 acceptance block does not use it as a prohibition.

Task +0xD0 points to a separate local work block. Local +0 is an unsigned phase byte; +1 is signed camera choice; +2 is signed timer-warning state; +4 is a signed 16-bit frame counter; +6 is an unsigned 16-bit input-repeat counter; +8 stores the previous 32-bit input mask. Local +0x0C, +0x10, +0x18 and +0x1C hold camera, HUD, swimmer and fade task references; +0x14 is a native scheduler-group parent task pointer. The callback requires this work pointer at entry: it reads the previous input and repeat fields before its phase switch. Phase 0 does not allocate the local work block.

Phase 4 frame 1 constructs the local File 69 fade and sets its alpha targets. Phase 4 frame 20 prepares resources, selects player action 0xC4, places the actual player at (0,-454,190), initializes player angles and control fields, constructs or configures the local camera, and emits native audio event 0x0064. Room coordinates alone do not reproduce this scheduled construction edge.

The instruction presentation already exists after phase 4 frame 20: actual player position (0,-454,190), action 0xC4, local control fields, fade and intro camera. There is no HUD or swimmer proxy at this stage. Ordinary nonedge phase-4 frames, including frame 21, run the common camera-copy and input-history tail without constructing the phase-6 graph or starting the frame-40 scenario.

Yae action 0xC4 selects a native no-op update callback. Together with the native control-entry state and the input-control fields cleared at phase 4 frame 20, this preserves the instruction pose before swimming begins. It is not evidence that a general busy or pause flag disables all player physics.

The intro camera uses immediate setters: distance 2560, eye (0,-354,-110), and look (0,-404,190). These setters update the camera scalar fields and clear their interpolation rates. They do not require the later phase-6 20-tick interpolation interval, but they also do not immediately refresh the projection descriptor.

The scheduled camera callback writes six floats into the first 24 descriptor bytes: eye XYZ at +0x00/+0x04/+0x08 and look XYZ at +0x0C/+0x10/+0x14. It writes the rounded unsigned 16-bit distance at descriptor +0x1A; the intro value is 0x0A00. The camera task stores its descriptor pointer at +0x6C. Allocation alone can still leave the old incoming world-camera descriptor in that storage.

Controller entry obtains the current world-camera presentation record through D_801FC628_5B8538. It decodes the descriptor address from the unsigned word at record +0x2C with mask 0x8FFFFFFE. The common tail calls func_80012900_13500(camera,destination), copying exactly 96 bytes from the camera descriptor to that decoded destination. Correct intro eye, look and distance in both descriptors establish presentation readiness independently of whether the camera or controller runs first that frame.

Phase 4 frame 40 starts instruction scenario 0x0177 and enters phase 5. Phase 5 only waits for that scenario to become idle before selecting phase 6 at frame 0. A controlled continuation that omits these instructions can omit those two branches; it must retain the native construction work at phase 4 frames 1 and 20 and phase 6 frame 1.

Phase 6 frame 1 suspends the ordinary player task, creates the local HUD, initializes its timer to 50 seconds (1500 raw ticks), adds the camera display record, and constructs the local swimmer proxy at (0,-350,264). It configures camera targets for zoom 3840, eye (0,190,-315), and look (0,swimmer Y+50,swimmer Z). A direct jump to phase 7 would omit this graph.

The File 69 fade is separate from the world-start fade. Its local task stores floating duration at +0x60, current alpha at +0x64, target alpha at +0x68 and step at +0x6C; the default duration is 16. The target setter computes abs(target-current)/duration, and the scheduled fade advances by that step. Phase 4 frame 20 targets alpha zero, producing the native intro fade-in. Alpha zero draws no opaque fullscreen cover. Repeating the target setter recalculates the step and changes that linear progression.

Phase 6 frame 20 selects camera mode 2 and active phase 7. The preceding 20-tick native interval allows the camera interpolation to settle; no new camera, HUD or swimmer is constructed at frame 20. A hidden preparation interval can preserve this native wait while holding the timer and swimmer input until visible play is ready.

Gameplay readiness requires a scheduled camera update and the controller's later copy of its projection descriptor, a fully initialized HUD with live display buffers and sprite objects, and the swimmer callback having naturally advanced from phase 0 to phase 1. A nonnull allocated proxy or camera is insufficient. The proxy initialization selects player action 0xCB and copies the training position to the actual Yae object.

Instruction scenario 0x0177 stages audio command 0x0292 before its final instruction text. This inspected path does not contain the 0x0052 command used by other challenge introductions. The identity of the audible song is not established here. If a continuation omits scenario 0x0177, it must supply command 0x0292 once at its prepared gameplay edge. Preserve the original scenario's audio ownership when the normal sign route runs.

Active phase 7 keeps camera choice and swimming input local. Every 40 signed frame counts it chooses two random horizontal obstacle indices in 0..6, resampling the second up to 20 times to seek a separation of at least two. It spawns both obstacles at Y=400 and the local swimmer Z.

The active tail reads this controller's swimmer height, updates the local HUD progress value to integer(Y+440), and selects failure phase 10 when the displayed countdown is zero or the swimmer is below -440. A swimmer above 380 selects success phase 9. These are native local-player checks, not a room-wide activity flag.

Success phase 9 sets interim packed flag 0x001E and runs its victory animation before cleanup phase 11. Failure phase 10 sets packed flag 0x001D and runs its own native animation before phase 11. At phase 11 frame 20, the camera, swimmer and HUD are destroyed, normal player presentation is restored, and the native return or reward continuation is selected.

Phase 9 reads the swimmer position unconditionally before its frame switch, and phase 9 frame 1 writes the swimmer victory phase without a null guard. Phase 10 frame 1 likewise writes the swimmer failure phase without a null guard. These terminal phases require the initialized phase-6 swimmer graph. Phase 11 frame 20 separately tests camera, swimmer and HUD references before deletion, allowing cleanup of an intro graph that has no HUD or swimmer. Bypassing phase 9 also bypasses interim success flag 0x001E, so nullable cleanup alone does not reproduce native success and reward handling.

On success, phase 11 frame 40 starts scenario 0x0176 and enters phase 12. The success branch of that scenario grants Mermaid ability by writing 1 at save-block offset +0xF0 and sets packed flag 0x001F. Phase 12 waits for dialogue completion, releases local control, and returns the controller to sign phase 1. Interim flag 0x001E is distinct from the permanent ability and reward flag.

## Notes

- The root local block is pointer-based; the swimmer and obstacle task state at +0xD0 is inline. Do not apply one layout to another task type.
- Exact frame tests at 1, 20, 40 and 60 perform constructors, audio and cleanup. Assigning a later phase/frame can skip required native work. Preserve initialized task identities, resource residency and generation before reading the graph.
- Local camera choice, input history, task references and the scheduler-group parent pointer are not portable state. A successful result does not make its reward complete before scenario 0x0176 has run.
- The ordinary-world return and the success dialogue have different continuations. Do not start a replacement room transfer before camera, swimmer and HUD cleanup, or infer saved-return fields from another challenge.
- The trial selects native Yae action 0xCB through its movement proxy. These findings do not establish a fish-tail mesh switch or a separate Mermaid-form flag.
- The native story-flag shortcut is tied to the second controller held-state field at full system +0x3B092. This trace does not establish that first-controller Start writes that field.
- File 69 uses native segment 0x11 even though raw callback addresses use the 0x08000000 range. The required callback preparation translates a raw address to the registered File 69 base plus its offset before dispatch. Imported callback references use the same base-plus-offset representation. A legacy segment resolver applied directly to a raw 0x08 callback can produce a different value; do not write that legacy result into a scheduled callback field or treat a static representation difference as an observed runtime failure.
- Execute construction through the normal scheduled task slots. Repeatedly invoking the controller in one game frame can replay its shared tail and does not replace the swimmer, camera and HUD initialization that must run on their own schedules.
- The ordinary world-start fade must finish normally. The native world-start routine clears its room-start busy state only after func_80036860_37460 reports completion; holding that fade opaque or suppressing its callback can prevent player readiness indefinitely. This world-start fade is separate from the File 69 training fade.
- Visibility masking is separate from native construction and camera readiness. These findings do not establish global VI black-state ownership or prove that a local cover owner may release a black state requested by another native subsystem.
- Keep intro presentation readiness separate from gameplay readiness. Waiting in the prepared phase-4 intro requires a correctly updated and copied camera descriptor, while the later active game additionally requires its own initialized HUD and swimmer. Constructing the swimmer early moves the actual player to proxy Y+15 and proxy Z+16, replacing the intro pose and coordinates.
- The decoded world-camera descriptor is a native tagged-pointer field. Preserve mask 0x8FFFFFFE and validate the resulting native pointer before reading or copying its 96 bytes. The current world-camera presentation record is distinct from the local camera task and from the player body.
- Advancing a phase-4 wait through native phase 5 when its instruction scenario is absent immediately selects phase 6. A retained nonedge frame must execute only once per normal scheduled controller slot, preserving exact constructor and scenario edges.
- Do not select native success or failure phases on a graph without its swimmer. The nullable phase-11 cleanup path is not a substitute for the success flag and reward work performed by phase 9.
