`func_801FA420_5B6330` · **Function**

Records native room-entry state plus setup and option values, then selects final transition marker 9.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x801FA420` | `0x005B6330` | `.file_11` |

Native code size: **132 bytes**.

## Signature

```c
void func_801FA420_5B6330(uint16_t room_id, int16_t x, int16_t y, int16_t z, uint16_t camera, uint32_t setup_value, uint16_t option);
```

## How it works

Forwards the room, XYZ, and camera values to func_801FA4FC_5B640C with marker_mode 0, which selects marker 1.

Stores setup_value and option in additional native transition fields, then ORs 0x08 into the same marker byte at system +0x3AE29 that the inner helper set to 1. The wrapper therefore finishes with marker 9.

The verified Ebisumaru entry supplies room 0x01E1, XYZ (0, 0, 0), camera 0, setup value 0x50, and option 0; its caller then queues scheduler callback 0x800354B4.

The sweets challenge exit calls this helper after restoring its saved 48-byte statistics block, using room 0x016D, XYZ (0,7,1), camera 0x0100, setup 0xA0 and option 0.

One native camera-initialization path uses a nonzero setup word independently of marker bit 0x08; another path reads that bit together with the setup word and option halfword. These fields are part of the surrounding room/camera lifecycle.

The separate native entry handler queues scheduler callback 0x800354B4 after preparing these fields. This helper call by itself does not reproduce that surrounding lifecycle.

## Notes

- This helper prepares native state but does not queue the scheduler callback itself.
- The semantic meanings and valid ranges of setup_value and option are not established beyond the observed sweets challenge entry and exit calls.
- The basic destination setter and saved-history request helper do not establish this same setup/option contract. Preserve the fields required by the verified native entry or exit path.
