`func_8002C9D4_2D5D4` · **Function**

Tests static and registered dynamic collision geometry and copies a 0x48-byte nearest-hit record to the caller.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x8002C9D4` | `0x0002D5D4` | `.main` |

Native code size: **704 bytes**.

## Signature

```c
extern void *func_8002C9D4_2D5D4(
    void *out, float x, float y, float z,
    float dx, float dy, float dz, float max_distance);
```

## How it works

The query considers static level collision and currently registered dynamic collision geometry, selecting the nearest hit by squared distance. It does not require a playable-player task.

The output begins with the six input floats at offsets +0x00 through +0x14. Hit displacement from the query origin is stored as three floats at +0x18/+0x1C/+0x20; the hit surface normal is at +0x24/+0x28/+0x2C.

The unsigned 16-bit hit field is at +0x38 and the float squared hit distance is at +0x3C. The two 32-bit pointer slots at +0x40/+0x44 identify dynamic collision object/task storage when supplied by that path.

Recover a world-space hit point by adding the displacement to the original query origin. Native caller 0x801CF3A0 uses that exact operation.

The dynamic ray path initializes its nearest squared-distance threshold to 2000.0 independently of max_distance. Dynamic hits at distances beyond approximately 44.72 world units can therefore be omitted even when max_distance is larger.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `out` | `void *` | Writable, four-byte-aligned storage for the full 0x48-byte query record. |
| `x, y, z` | `float` | World-space ray origin. |
| `dx, dy, dz` | `float` | Nonzero normalized ray direction. |
| `max_distance` | `float` | Positive maximum distance to query. |

## Return value

Returns the out pointer. The returned pointer is not a hit indicator; read the unsigned 16-bit hit field at out +0x38, where 0x7FFF indicates a hit.

## Usage example

```c
#include <stdint.h>

typedef struct NativeWorldRayHit {
    float origin[3];
    float direction[3];
    float displacement[3];
    float normal[3];
    uint8_t opaque_30[8];
    uint16_t hit;
    uint16_t opaque_3a;
    float distance_squared;
    void *dynamic_object;
    void *dynamic_task;
} NativeWorldRayHit;

_Static_assert(sizeof(void *) == 4, "Native pointers require MIPS32");
_Static_assert(sizeof(NativeWorldRayHit) == 0x48, "Native query layout");

extern void *func_8002C9D4_2D5D4(
    void *out, float x, float y, float z,
    float dx, float dy, float dz, float max_distance);

/* Call only in a valid loaded scene. */
int query_nearby_ground(float x, float y, float z, float *ground_y)
{
    NativeWorldRayHit result = {0};
    if (!ground_y) return 0;
    func_8002C9D4_2D5D4(&result, x, y, z, 0.0f, -1.0f, 0.0f, 32.0f);
    if (result.hit != 0x7FFFu) return 0;
    *ground_y = y + result.displacement[1];
    return 1;
}
```

The MIPS32 layout and hit check match the native record. The downward ray is limited to 32 world units so the dynamic nearest-hit threshold cannot hide a hit within this cast. Longer paths need multiple short casts in order.

## Notes

- For long casts that must include dynamic meshes, split the path into segments safely below sqrt(2000), such as 32 world units, and stop at the first hit. Normalize the nonzero direction before casting each segment. Increasing max_distance alone does not extend the dynamic nearest-hit threshold.
- Run only while the scene collision data and native dynamic actor lists are loaded and valid. The query reads scene-owned mesh resources and is not safe to treat as an independent geometry library during loading or teardown.
- The function copies 72 bytes even when there is no hit. Allocate the whole record, preserve its native layout, and check the hit field before using hit displacement, normal, distance or dynamic pointers.
- Bytes +0x30 through +0x37 and +0x3A through +0x3B have not been fully decoded. Preserve them as opaque storage. Dynamic pointers are scene-owned; do not retain them across task deletion or room changes.
- This is a ray query, not a full swept cylinder or body solver. A single ray does not establish clearance for a character-sized volume.
