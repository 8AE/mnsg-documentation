`func_08000B58_6F0D68` · **Function**

Runs the two native explosion modes: one visual effect and one outgoing contact sphere that can cause ordinary player damage.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x08000B58` | `0x006F0D68` | `.file_42` |

Native code size: **724 bytes**.

## Signature

```c
void func_08000B58_6F0D68(void *task, void *object);
```

## How it works

The initializer selects model resource 0x0191, variant 8, and starts a lifetime counter at 30. The callback distinguishes a visual mode from a contact mode using task mode flags.

During phase 0, mode flag 0x01 (spawn group 0) leaves outgoing kind +0x4C at zero, uses the local explosion material, and creates a separate visual-effect task.

With mode flag 0x04 (spawn group 1), it uses a different local material. On the first phase-1 update it calls func_80218DA8_5D4278 to install a descriptor whose stored radius is 120, then sets outgoing kind 1. The sphere is transformed by explosion object position and scale, so radius 120 is a local descriptor value rather than a fixed world-space radius.

Native player contact handling accepts ordinary type-1 contact under its own collision, defense and invulnerability gates. For this explosion the damage byte is 1, and the accepted path applies a signed health delta of -1 through the normal player-health routine.

The signed halfword lifetime at task +0x8A starts at 30 and decrements once per phase-1 update. When the entry life value is already zero, the callback deletes the task; the zero-life update is the expiry boundary.

## Return value

No return value.

## Usage example

```c
extern void func_08000B58_6F0D68(void *, void *);
typedef void (*NativeTaskCallback)(void *, void *);

/* Observe callback identity; the native scheduler owns invocation. */
NativeTaskCallback documented_explosion_callback(void)
{
    return func_08000B58_6F0D68;
}
```

Returns the verified callback identity without advancing an explosion or applying contact.

## Notes

- This callback changes native task state, creates a visual-effect task in one mode and configures contact in the other. Let the native scheduler and collision/player pipelines run it once in their normal lifecycle.
- A visual cue alone is not proof that the damaging contact was accepted. Native collision and player intake retain their defense, control-state and invulnerability gates.
- Do not replay this callback or transmit raw task/object pointers to reproduce an explosion on another process.
- Material and model references belong to local native resource/object state. Do not treat those runtime handles as transferable actor pointers.
