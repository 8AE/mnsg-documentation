`func_80024038_24C38` · **Function**

Sets one bit in the packed game-flag bank without changing the other bits in that byte. Native event logic uses this entry point to record progression or encounter state.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80024038` | `0x00024C38` | `.main` |

Native code size: **80 bytes**.

## Signature

```c
extern void func_80024038_24C38(int flag_id);
```

## How it works

For valid nonnegative IDs, selects byte (flag_id >> 3) & 0xFF and ORs it with 1 << (flag_id & 7). Setting an already-set flag leaves the bank unchanged.

An entry hook on this function can observe native flag writes. Direct writes to the flag bank bypass that hook; reaching the same stored bit does not necessarily execute the same callbacks.

This routine only changes a bit. Its decompiled body does not save to storage, spawn a reward, or finish a boss death animation.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `flag_id` | `int` | Known flag bit index, 0x000–0x7FF. |

## Return value

No return value.

## Usage example

```c
extern void func_80024038_24C38(int flag_id);

static void set_known_game_flag(unsigned int flag_id)
{
    if (flag_id < 0x800u) {
        func_80024038_24C38((int)flag_id);
    }
}
```

Call from game logic with a documented flag ID when the associated event is actually complete. This helper validates the range, but does not perform the event or persist a save.

## Notes

- There is no native bounds check; larger IDs alias the 256-byte flag bank.
- Progression flags can affect later game logic. Set only flags whose meaning and required event sequence you have established.
