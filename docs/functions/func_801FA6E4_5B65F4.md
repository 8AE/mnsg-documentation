`func_801FA6E4_5B65F4` · **Function**

Copies the saved room and arrival fields into pending transition state and selects a return marker.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x801FA6E4` | `0x005B65F4` | `.file_11` |

Native code size: **204 bytes**.

## Signature

```c
void func_801FA6E4_5B65F4(char marker_mode);
```

## How it works

Copies the saved room halfword from system-state +0x3ADFC to pending room +0x3AFE0.

Copies saved XYZ halfwords from +0x3AFF8/+0x3AFFA/+0x3AFFC to pending +0x3AFE4/+0x3AFE6/+0x3AFE8, and copies the saved orientation halfword at +0x3AFFE to pending +0x3AFEA.

Writes system-state marker byte +0x3AE29 as 4 for nonzero marker_mode, or 1 for zero.

The separate pending packed camera-start parameter at +0x3AFE2 is not written by this helper. The base destination heading is stored at +0x3AFEA.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `marker_mode` | `char` | Zero selects marker 1; any nonzero value selects marker 4. |

## Return value

No return value.

## Usage example

```c
extern void func_801FA6E4_5B65F4(char marker_mode);

/* Invoke at the native exit boundary after room history is valid. */
void record_saved_room_return(void)
{
    func_801FA6E4_5B65F4(1);
}
```

This selects marker 4 using the native saved room and arrival fields. The native exit controller remains responsible for the rest of the transition lifecycle.

## Notes

- Requires valid initialized system state and saved room history from the surrounding native entry lifecycle.
- This routine records pending transition fields; it does not by itself execute the room transition, restore challenge statistics or grant a reward.
- The copy itself does not prove whether every caller originally saved a camera angle or player facing into +0x3AFFE. Keep the saved halfword distinct from the separate pending packed camera-start field.
