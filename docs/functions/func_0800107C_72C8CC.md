`func_0800107C_72C8CC` · **Function**

Handles the Mermaid training player's own swimming input and contact impulse, then copies its movement proxy position to the current local Yae object.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x0800107C` | `0x0072C8CC` | `.file_69` |

Native code size: **1040 bytes**.

## Signature

```c
void func_0800107C_72C8CC(void *task, void *object);
```

## How it works

This movement task stores state inline at task +0xD0: signed phase byte +0xD0, unsigned input-repeat byte +0xD1, signed frame halfword +0xD2, previous 32-bit input mask +0xD4, floating vertical velocity +0xD8, and floating contact impulse +0xDC.

Initialization sets task entity halfwords +0x5C and +0x5E to 0x033A, configures the native collision bounds, changes local player presentation and scale, and selects player action 0xCB.

In active phase 1, an A-button press edge adds 1 to vertical velocity. The signed horizontal input changes X by input/20 and clamps X to [-80,80]. Native gravity clamps vertical velocity to [-2,2]. Contact status bit 0x80 sets a -48 impulse, which is halved during subsequent movement updates.

After updating the proxy object, the callback writes the actual current player object to X=proxy X, Y=proxy Y+15 and Z=proxy Z+16. This explains why the normal local-player movement stream observes the training pose.

The controller computes climbed height from integer(proxy Y+440). Because the displayed player object is 15 units higher, its equivalent height is integer(player-object Y+425). Keep the proxy and displayed-player coordinate spaces distinct.

An inline phase request of 0xFF is converted to victory phase 3 with initial vertical velocity 10; 0xFE selects failure phase 4. These transitions belong to the matching controller result sequence.

This exposes callback identity without running initialization, rendering, movement, collision handling or result cleanup a second time. The resident overlay and native task lifetime remain required.

## Notes

- The routine writes global current-player state, animation and transforms. Running it for another player is not a general animation or position update API.
- The contact read participates in native collision behavior. Do not replay the callback to restore a scalar checkpoint or to fabricate an extra collision response.
- Keep each swimmer's input, camera and physical task independent. The initialized entity 0x033A is also used by obstacle tasks, so entity identity alone is insufficient.
- Construction returns before this callback has run phase 0. Before revealing a prepared trial, let the native scheduler initialize phase 1 so the actual player scale, action 0xCB and proxy-to-player transform have been established.
