`func_800141C4_14DC4` · **Function**

Looks up a dynamic scene-registry resource and returns its stored value, including native type tags.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x800141C4` | `0x00014DC4` | `.main` |

Native code size: **84 bytes**.

## Signature

```c
extern void *func_800141C4_14DC4(unsigned int file_id);
```

## How it works

Scans registry entries beginning at 0x80167FC0 until a matching ID or the zero-ID terminator. A match returns the stored resource data pointer.

File ID zero returns null. A nonzero ID absent from the registry returns target pointer 0xFFFFFFFF.

Control Machine projectile resource file 0x2E has native resource category 0x11. When registered, its data base is stored with tag bit 0x40000000, and this lookup returns that stored value unchanged.

This lookup searches the dynamic scene-resource registry only. The native world loader directly loads common File12 code to fixed destination 0x8020D2A0 without inserting a dynamic registry entry.

Scans D_80167FC0_168BC0 until a matching file ID or the zero-file sentinel. ID zero returns null; an absent nonzero ID returns 0xFFFFFFFF.

Use this to obtain loaded data and to preflight segmented-pointer resolution. A successful lookup does not extend the resource lifetime past scene teardown.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `file_id` | `unsigned int` | Native resource file ID, such as 0x2E for the Control Machine projectile. |

## Return value

Stored resource value, including any native type tag; null for file ID 0; target pointer 0xFFFFFFFF when not found.

## Usage example

```c
extern void *func_800141C4_14DC4(unsigned int file_id);

void *find_control_machine_shot_resource(void)
{
    void *resource = func_800141C4_14DC4(0x2E);
    if (!resource || resource == (void *)(unsigned long)0xFFFFFFFFu)
        return 0;
    /* Preserve the registry value; it is not an actor or task pointer. */
    return resource;
}
```

The Control Machine shot lookup demonstrates the null and missing-file checks while preserving the tagged registry value for the resource consumer.

## Notes

- Check both null and the -1 sentinel before dereferencing. A non-null pointer alone does not prove the file was found.
- Registry entries have scene/overlay lifetimes; a pointer retained across a resource reload may be stale.
- A tagged resource value is not an actor or task pointer. Do not require it to pass actor-pointer address-range checks; check this API's null and 0xFFFFFFFF sentinels and preserve the returned value unchanged when a resource consumer expects it.
- A missing entry is not a general test for executable-overlay residency. In particular, File12 world functions can be available through the fixed native loader while file ID 0x0C is absent from this registry.
- Checking only null is insufficient: missing nonzero files return (void *)-1.
- Registered bases may carry the cache tag used by the engine. Only normalize addresses according to the destination subsystem.
- A successful lookup does not extend the resource lifetime beyond the current scene.
