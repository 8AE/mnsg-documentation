`func_80002F54_3B54` · **Function**

Advances the native game-over state machine that offers continue or goodbye, and returns to the start sequence on goodbye.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80002F54` | `0x00003B54` | `.main` |

Native code size: **412 bytes**.

## Signature

```c
extern void func_80002F54_3B54(void);
```

## How it works

This handler runs while the main system step at full-system +0x3ADD4 is 0x0E. Native death paths select that step only when the runtime life count reaches zero, so it is the game-over screen rather than ordinary gameplay.

A substate byte at full-system +0x3ADD6 drives a five-value sequence: 0 marks the transition, 1 initializes the game-over overlay and its task, 2 starts that task, 3 waits for it to finish, and 4 performs the exit.

At the exit substate, the completion byte at full-system +0x3ADD5 chooses the outcome. The value 1 restores saved state and selects step 0x0B; any other nonzero value runs func_8000383C_443C to tear down the overlay and selects step 3.

Step 3 is the start/sequence step that loads overlay file 0x16, and it is also selected by the ordinary world-teardown path, so this exit returns to the title flow instead of resuming the room.

The handler is dispatched once per frame while step 0x0E remains selected. Redirecting a game over to step 3 requires the teardown call before the step change, exactly as the native goodbye branch does.

## Return value

No return value.

## Usage example

```c
#include "modding.h"

extern void func_8000383C_443C(void);
extern void func_80003728_4328(unsigned char step);

/* Runs after the game-over handler on each frame while step 0x0E is selected. */
RECOMP_HOOK_RETURN("func_80002F54_3B54")
void leave_game_over(void)
{
    /* The native goodbye branch tears the overlay down before selecting the
     * start/sequence step. Do not change the step without that teardown. */
    func_8000383C_443C();
    func_80003728_4328(3);
}
```

The hook performs the same teardown plus step change the native goodbye branch uses. Guard the redirect so it only runs for a game over that should leave the flow.

## Notes

- The completion byte at +0x3ADD5 and the substate byte at +0x3ADD6 are separate fields; changing the wrong one does not advance the handler.
- Selecting another step without the native teardown can leave the game-over overlay and its tasks resident.
- The overlay identifiers and substates here are specific to the game-over flow; this is not a general menu interface.
