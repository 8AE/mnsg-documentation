`func_80004AF8_56F8` · **Function**

Copies or decays native controller state into the derived gameplay input records.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80004AF8` | `0x000056F8` | `.main` |

Native code size: **1824 bytes**.

## Signature

```c
extern void func_80004AF8_56F8(void);
```

## How it works

Updates the four 0x18-byte derived gameplay-controller records at D_800C7DB0_C89B0 from the native raw input records while both D_800C7AE2 and D_800C7AE3 are zero.

When either lock byte is nonzero, the function decays stick state and recomputes analog quantities without copying new buttons. Previously held/pressed values require explicit consideration; setting a lock is not equivalent to clearing the derived input.

A return hook observes or filters the completed derived sample. The scenario input sampler reads separate raw controller storage, so clearing derived gameplay buttons/stick at this boundary can leave native dialog input responsive.

Reads the native OS controller messages and updates raw input before completing the derived gameplay sample. Its return is a useful observation boundary after controller processing.

## Return value

No return value.

## Usage example

```c
#include "modding.h"
extern unsigned char D_800C7DB0_C89B0[0x60];

static unsigned short s_last_gameplay_buttons;

RECOMP_HOOK_RETURN("func_80004AF8_56F8")
void observe_gameplay_input(void)
{
    s_last_gameplay_buttons = *(unsigned short *)(D_800C7DB0_C89B0 + 2);
}
```

The native return hook reads controller-one held buttons after the derived input update. It does not modify raw input or introduce global control ownership.

## Notes

- Do not overwrite raw controller storage when the native scenario still needs to receive input.
- If filtering a derived record, preserve its connected-status halfword and respect scenario/room ownership.
- Calling this routine directly can block while waiting for an SI/controller message. Observe its normal native invocation instead of adding extra calls.
