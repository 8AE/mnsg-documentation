`func_080009C4_6B3C64` · **Function**

Runs an initialized Congo ray through its native fade and removal phase.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x080009C4` | `0x006B3C64` | `.file_29` |

Native code size: **592 bytes**.

## Signature

```c
extern void func_080009C4_6B3C64(void *ray_task, void *ray_object);
```

## How it works

The ray initializer starts unsigned-byte color/opacity scalar +0xEC at 64. The growing ray callback selects this fade callback after observing parent root +0xE8 bit 0x80.

Clears parent root +0xE8 bit 0x80 and tracks one of four directional yaw offsets from the parent according to the ray variant.

Subtracts two from the ray scalar +0xEC, clamps it at four, and updates the corresponding native ray colors. At four, requests native current-task removal.

Selecting the fade callback is sufficient to begin fading an initialized ray. No additional fade initializer resets its opacity.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `ray_task` | `void *` | Initialized ray task with a live parent root at +0xD0; the current scheduler task must be this ray. |
| `ray_object` | `void *` | The ray object supplied by the native scheduler, normally task +0x18. Both callback arguments are consumed. |

## Return value

No return value is used by the native callback convention.

## Usage example

```c
#include "modding.h"

static unsigned char observed_ray_fade;

RECOMP_HOOK("func_080009C4_6B3C64")
void observe_congo_ray_fade(void *ray_task, void *ray_object)
{
    if (!ray_task || !ray_object) return;
    observed_ray_fade = *(volatile unsigned char *)((char *)ray_task + 0xEC);
}
```

Observe the remaining fade scalar during its normal native callback. The hook preserves current-task ownership and leaves removal to the original routine.

## Notes

- Keep file_29, the initialized ray object and its parent root live. This routine assumes the ray initializer has already established its native resources.
- Removal uses the current scheduler-task pointer. Manually invoking this callback under another current task can remove the wrong task.
- Do not reset +0xEC to 64 on repeated state observations; doing so restarts the fade and prevents normal removal.
- The shared parent stop bit can be clear while a ray is already fading. The ray callback and remaining scalar describe its ongoing lifetime.
