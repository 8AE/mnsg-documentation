`func_080018E8_709328` · **Function**

Runs the native introduction, six targets and 100-second (3000-frame) Impact challenge, including carrying, throwing, result and exit phases.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x080018E8` | `0x00709328` | `.file_48` |

Native code size: **2748 bytes**.

## Signature

```c
void func_080018E8_709328(void *task, void *object);
```

## How it works

Task word +0xD0 points to its 60-byte work area. Work byte +0x00 is the phase, halfword +0x02 is yaw modulo 1024, signed halfword +0x04 is the phase frame, halfword +0x06 is the held-button repeat count, and word +0x08 is the previous held-button mask.

Work words +0x0C and +0x10 are native visual pointers; +0x14 is the timer HUD task pointer. Six target task pointers occupy +0x18 through +0x2C; three throwable task pointers occupy +0x30 through +0x38.

Phase 0 performs setup. Phase 3 starts introduction scenario 0x0173. Phase 4 waits for the instruction VM to be idle, then constructs the timer and six targets. Phases 1 and 2 implement local carrying/aiming and throwing. The timer starts at 100 seconds, represented by 3000 native frames.

Introduction scenario 0x0173 queues native audio command 0x0292 before its final instruction wait and text. After setting instruction flag 0x1B, it queues gameplay music command 0x0052 through func_80038BC8_397C8 and ends. The phase-4 VM-idle/HUD/target transition contains no audio call.

The terminal checks run from ordinary controller callbacks. Timer expiry is tested by signed timer word +0x84 divided by 30 equaling zero and selects phase 5. The controller then scans the six target result bytes; any target with byte +0xD1 equal to 1 selects phase 6, writes 3 to every target result byte, then writes 4 to the matching target byte. That final value is consumed by the target callback to advance its local balloon into the pop phase. The timer test precedes the target scan, so a target result can select phase 6 in the same callback after timer expiry selected phase 5.

The controller performs terminal child cleanup on the following callback when the phase frame is 1. It also owns the local camera and player reset path. The meanings of phases 5 and 6 as win/loss outcomes are not established by these native predicates alone.

## Notes

- Pointers and carry/throw state belong to this native controller graph. Preserve native child initialization and cleanup.
- The native target predicate is ANY one of the six result bytes equaling 1; do not describe it as requiring all six targets to be complete.
- The target hit bit is observed, but attribution of a specific cube through task +0x38 has not been established.
- The controller resets the local player and camera during its normal callback. Its state is not a transferable remote actor graph.
- Bypassing scenario 0x0173 also bypasses its gameplay-music command. Account for that local transition once when active play begins; do not replay the instruction scenario or submit its audio command every frame.
