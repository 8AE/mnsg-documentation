`func_0800127C_708CBC` · **Function**

Advances a target using inline task work and the native hit-status bit.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x0800127C` | `0x00708CBC` | `.file_48` |

Native code size: **1496 bytes**.

## Signature

```c
void func_0800127C_708CBC(void *task, void *object);
```

## How it works

This callback stores inline target work beginning at task +0xD0. It does not dereference task +0xD0 as a heap-work pointer.

The inline work begins with a phase byte at +0x00 and a signed completion byte at +0x01. The controller checks each completion byte for value 1.

Relative to inline task work, signed halfword +0x06 is the frame counter, signed halfwords +0x08/+0x0A are random intervals, float +0x0C is Y displacement, float +0x14 is the motion threshold, and word +0x18 is a visual child pointer.

Reads task word +0x68 bit 0x80 as native hit status and advances the target lifecycle.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `task` | `void *` | The matching live native task. |
| `object` | `void *` | Object supplied by the native scheduler for this task callback. |

## Return value

No return value.

## Usage example

```c
extern void func_0800127C_708CBC(void *task, void *object);

typedef void (*NativeTaskCallback)(void *, void *);

/* Observe identity without replaying the native lifecycle. */
NativeTaskCallback documented_callback(void)
{
    return func_0800127C_708CBC;
}
```

The native scheduler owns callback execution. This example returns the function address and does not allocate work, advance challenge state or replay a contact pass.

## Notes

- The hit-status bit does not establish the identity of the attacking cube. Task +0x38 must not be documented as that cube pointer without additional collision-path evidence.
- Use this target layout only for the matching callback; the challenge controller uses a heap pointer at the same task offset.
