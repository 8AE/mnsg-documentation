`func_0800127C_708CBC` · **Function**

Advances a rising target through native hit, interpolation, and wobble phases.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x0800127C` | `0x00708CBC` | `.file_48` |

Native code size: **1496 bytes**.

## Signature

```c
void func_0800127C_708CBC(void *task, void *object);
```

## How it works

This callback stores target work inline beginning at task +0xD0. The phase is a byte at +0x00; the signed result byte is +0x01; the signed frame counter is halfword +0x06; signed halfwords +0x08 and +0x0A are rapid-rise schedule values; current Y displacement is float +0x0C; desired Y is float +0x10; interpolation step size is float +0x14; and +0x18 holds a local balloon task pointer.

Before phase handling, interpolation runs when the step size is greater than 0.001. If the absolute difference between desired and current Y is strictly smaller than the step size, current Y snaps to the desired value and the step becomes zero; otherwise the callback moves by one step toward the desired value. Equality steps to the destination and clears the step on the following callback.

In phase 1, the signed comparison of schedule halfword +0x08 against the signed frame counter selects a 0.4 Y increment when schedule < frame, otherwise 0.05. A hit lowers current Y by 8, clamps it at -130, resets the frame counter, and switches to phase 3; the phase-1 rise body still runs in that callback. The faster rise can schedule later intervals through native random-number calls.

Phases 3 and 4 use a sine wobble while the signed frame counter is below 60: angle = signed-trunc((frame × 0x3C00) / 60), then converted to u16; scale = 1 + sine(angle) × 0.1 × ((60 − frame) / 60)^2, written to object +0x1C, +0x20, and +0x24. Phase 3 clears the result byte; a hit lowers current Y by 16, resets the frame, and switches to phase 4. A phase-4 hit resets current Y to -130 and the frame counter. When the signed frame counter becomes greater than 60, phases 3 and 4 return to phase 1. At frame 60 the scale is not updated, and phase 2 has no phase-body action; interpolation and the shared epilogue still run.

The phase-1, phase-3 and phase-4 hit branches read task +0x68 status bit 0x80 but do not clear it. The ordinary common damage pass clears that bit only after its actor-flag gate and a non-null task +0x38 attacker pointer. A source-free injected bit can therefore survive the post pass and repeatedly reset the target's hit-recovery frame and height.

The shared epilogue copies current Y to object +0x0C, increments the signed frame counter, and writes result byte 1 when current Y is strictly greater than -10. The native controller owns terminal admission: it observes the result byte and may replace it while advancing the challenge.

A result byte of 3 forces phase 7. A result byte of 4 increments the local balloon phase once through func_0800126C_708CAC, then forces phase 7.

## Usage example

```c
extern void func_0800127C_708CBC(void *task, void *object);

typedef void (*NativeTaskCallback)(void *, void *);

/* Observe identity without replaying the native lifecycle. */
NativeTaskCallback documented_callback(void)
{
    return func_0800127C_708CBC;
}
```

The native scheduler owns callback execution. This example returns the function address and does not allocate work, advance challenge state or replay a contact pass.

## Notes

- The result byte is native controller state, not a network-ready completion event. Do not grant an authoritative result from a separately predicted height crossing.
- The hit-status bit does not establish the identity of the attacking cube. Task +0x38 must not be treated as that cube pointer without additional collision-path evidence.
- Use this target layout only for the matching callback; the challenge controller uses a heap pointer at the same task offset. The balloon pointer at +0x18 in this inline work is local and must not be transmitted.
- A supplied hit must be consumed once at the target's naturally scheduled update. Preserve a pre-existing native contact bit and unrelated status bits; do not fabricate task +0x38 or set status bit 0x00040000 to force consumption, since the latter enters actual damage handling.
