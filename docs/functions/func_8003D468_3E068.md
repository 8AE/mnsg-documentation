`func_8003D468_3E068` · **Function**

Prepares the native scenario VM, resetting shared interpreter and dialog configuration.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x8003D468` | `0x0003E068` | `.main` |

Native code size: **548 bytes**.

## Signature

```c
extern int func_8003D468_3E068(void *script, int file_id);
```

## How it works

The native scenario interpreter executes 32-bit instructions and follows pointers to 16-bit glyph/control streams. This initializer resets the VM input/configuration state and selects its scenario/resource context.

Calling with a null script and file_id -1 clears the program counter and resource context. It does not allocate a message window. The initializer also clears transient native flag 0x82; callers preserving an existing flag state must restore that state when their own interaction ends.

A private dialog must first verify that the scenario manager exists and no scenario or message window currently owns the shared interpreter. Reset the interpreter before allocating and configuring a new window, then publish a persistent instruction stream only after allocation succeeds.

The no-file reset selects controller source 3 (merged controllers), character -1, window slot 0 with origin (24,24), style 0 and animation 0, and typing mode 1. It does not free existing windows; callers must finish ownership-aware window cleanup separately.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `script` | `void *` | Scenario instruction stream, or null for the established reset operation. |
| `file_id` | `int` | Scenario resource context; -1 is the established no-file/reset value. |

## Return value

Returns 0 when the scenario-manager pointer is null; otherwise returns 1 after resetting or starting the scenario.

## Notes

- This function mutates shared scenario state; it must not reset a conversation or replacement scenario owned by another native task.
- A successful reset does not prove that a window was allocated or that the world is safe for interactive UI.
- Keep instruction arrays, text streams and callback targets alive until the interpreter and closing animation finish.
- Native callers may establish player control locks before calling this initializer. An entry hook cannot assume those bits still belong to the previous interaction; do not clear replacement locks during cleanup.
