`func_08000E2C_6F103C` · **Function**

Waits for the native ground-status gate, creates two explosion children, and retires the bomb task.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x08000E2C` | `0x006F103C` | `.file_42` |

Native code size: **516 bytes**.

## Signature

```c
void func_08000E2C_6F103C(void *task, void *object);
```

## How it works

In its active phase, waits until task status +0x68 bit 0x20 is clear. It then creates the group-0 visual explosion child first, creates the group-1 damaging explosion child second, and deletes the bomb task after both constructions.

The callback does not choose a player target or revise the bomb's position. Position selection and bomb creation occur in the challenge controller.

The two direct children inherit the grounded bomb transform. Their context-copy helper is entered before the direct-child allocator finalizes its bank/resource fields; the File42 caller installs the resident File42 bank and resource base afterward.

The two spawn calls use zero owner-relative XYZ offsets, so both child objects begin at the grounded bomb origin rather than at a separately selected target.

Only after both children have completed their bank/mode/resource setup does the bomb callback request deletion of the current parent task. The native deletion wrapper enters cleanup before later unlinking the task; the verified bomb path does not pre-set task status +0x68 bit 0x02 before that wrapper entry.

## Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `task` | `void *` | Live bomb task supplied by the native scheduler. |
| `object` | `void *` | The bomb's native object supplied by the scheduler. |

## Return value

No return value.

## Usage example

```c
extern void func_08000E2C_6F103C(void *task, void *object);

typedef void (*NativeTaskCallback)(void *, void *);

/* Observe the callback identity without advancing or retiring a bomb. */
NativeTaskCallback documented_bomb_callback(void)
{
    return func_08000E2C_6F103C;
}
```

Returns the verified callback identity without creating children or changing task state. The native scheduler owns invocation.

## Notes

- The task and object must be valid within the matching native scheduler lifecycle. This callback includes child creation and task retirement; it is not a position-only query.
- This callback emits two native children, performs audio and deletes its parent. Do not call it again to reproduce visual or contact state.
