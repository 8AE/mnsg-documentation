`D_80209B9C_5C5AAC` · **Variable**

Five file_0C pointers select native room, floor and vertical-rule tables.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80209B9C` | `0x005C5AAC` | `.file_11` |

## Signature

```c
extern const unsigned char *D_80209B9C_5C5AAC[5];
```

## How it works

Each table contains three-byte records: raw room ID, zero-based floor and special vertical-rule ID. A room byte of 0xFF ends the table.

Some rooms appear more than once because they span floors. Native lookup starts with the first matching record; the height updater then resolves the actual floor. There are 116 distinct dungeon/room pairs.

The initial table pointers are 0x80209A00, 0x80209A50, 0x80209AA4, 0x80209AF4 and 0x80209B48. These are overlay data, not save-state pointers.

## Usage example

```c
extern const unsigned char *D_80209B9C_5C5AAC[5];

int initial_room_floor(unsigned int dungeon, unsigned int room)
{
    const unsigned char *row;
    if (dungeon >= 5 || room >= 255) return -1;
    for (row = D_80209B9C_5C5AAC[dungeon]; row[0] != 255; row += 3)
        if (row[0] == room) return row[1];
    return -1;
}
```

The example illustrates the native interface and its required state.

## Notes

- Only access this layout while its owning overlay and task are active. Task-pool addresses can be reused after destruction.
- This example reads only the first matching floor. Apply its special height rule for rooms spanning floors.
