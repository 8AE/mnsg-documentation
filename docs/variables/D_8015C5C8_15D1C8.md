`D_8015C5C8_15D1C8` · **Variable**

Pointer to the complete native system structure, including two graphics banks and gameplay state.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x8015C5C8` | — | `ABSOLUTE_SYMS` |

## Signature

```c
extern unsigned char *D_8015C5C8_15D1C8;
```

## How it works

A 16-bit world-frame counter is stored at structure +0x3ADCE. It can identify the native frame for effects and state that must advance once per world update.

Congo breath emission uses this counter modulo 15. The system step byte also chooses the handler dispatched by func_80002040_2C40.

Used by system-step dispatch and scene-loading functions. The byte-pointer declaration allows access to selected recovered offsets, including the prepared destination at +0x3AFE0.

Native initialization stores 0x8008CCC0 in this pointer. The static symbol D_800BCCC0_BD8C0 is an interior alias at system base +0x30000, so offsets relative to that alias are 0x30000 smaller than offsets relative to this full pointer.

The structure begins with two graphics-bank records of 0x1D6D8 bytes each. Each contains 10,640 Gfx commands, 540 64-byte matrices, four viewports and the remaining native workspace fields. The current bank index is D_800C7A72; the matrix array begins at bank +0x14C80.

## Known values

### System structure fields {#system-fields}

Dereference this pointer once, then use these offsets from the full system structure base (0x8008CCC0 in the US executable). D_800BCCC0_BD8C0 is an interior alias 0x30000 bytes farther into the same structure.

| Offset | Storage type | Meaning |
| --- | --- | --- |
| `0x3ADCA` | `uint8_t` | Game-loop timing/control byte; the system-step setter writes 2. |
| `0x3ADCE` | `int16_t` | Game-loop/frame counter; a running numeric counter, not a state ID. |
| `0x3ADD4` | `uint8_t` | Main system step. Known entries are listed below. |
| `0x3ADD5` | `uint8_t` | Main-step completion/substate byte; the step setter clears it to 0. |
| `0x3AE16` | `int16_t` | Native start-sequence gate. Zero is the cleared value used for normal gameplay; nonzero values must retain their native sequence meaning. |
| `0x3AE20` | `uint8_t` | Player control mask (D_800C7AE0). Either low bit in mask 0x03 suspends the native late player collision handlers. |
| `0x3AE23` | `uint8_t` | Scripted player input state (D_800C7AE3). The native move-toward and input-playback paths set it while supplying scripted input. |
| `0x3AE29` | `uint8_t` | Destination-transition marker; the warp destination helper writes 1. |
| `0x3AE3A` | `uint16_t` | Seventh argument of the warp destination helper; individual values are not yet interpreted. |
| `0x3AE3C` | `uint32_t` | Eighth argument of the warp destination helper; individual values are not yet interpreted. |
| `0x3AFE0` | `uint16_t` | Destination room/stage ID. Use the room table on D_800C7AB2. |
| `0x3AFE2` | `int16_t` | Destination player rotation. |
| `0x3AFE4` | `int16_t` | Destination player X position. |
| `0x3AFE6` | `int16_t` | Destination player Y position. |
| `0x3AFE8` | `int16_t` | Destination player Z position. |
| `0x3AFEA` | `int16_t` | Destination camera rotation. |

### Known main-system steps {#known-system-steps}

These are selected established values of the byte at full-system offset +0x3ADD4. A step change depends on initialized native callbacks and related state; this is not a complete state-machine enum.

| Raw value (hex) | Raw value (decimal) | Meaning |
| --- | --- | --- |
| `0x07` | `7` | Native start/title/demo sequence path. |
| `0x0C` | `12` | Scene load/warp sequence path. |

### Graphics-bank layout {#graphics-bank-layout}

Offsets are relative to one bank, beginning at full system base + bank_index × 0x1D6D8. There are two banks; these fixed arrays are distinct from CPU task and display-record storage.

| Bank-relative offset | Storage | Meaning |
| --- | --- | --- |
| `+0x00000` | `Gfx[10640]`, 8 bytes each | Native graphics-command array, total 0x14C80 bytes. |
| `+0x14C80` | `Mtx[540]`, 64 bytes each | Submitted fixed-point matrices, total 0x8700 bytes. |
| `+0x1D380` | `Vp[4]`, 16 bytes each | Four native viewports. |
| `+0x1D3C0` | `unsigned char[600]` | Additional native workspace; individual fields are not interpreted here. |
| `+0x1D618` | `unsigned char[128]` | Additional native workspace; individual fields are not interpreted here. |
| `+0x1D698` | `unsigned char[64]` | Final native workspace, ending at bank offset 0x1D6D8. |

## Usage example

```c
extern unsigned char *D_8015C5C8_15D1C8;

unsigned short world_frame(void)
{
    if (!D_8015C5C8_15D1C8) return 0;
    return *(volatile unsigned short *)(D_8015C5C8_15D1C8 + 0x3ADCE);
}
```

The example shows the documented native data layout or call sequence. Use it only while the relevant game state and resources are valid.

## Notes

- The symbol contains a pointer; it is not the first byte of the structure itself.
- Changing the world clock affects every subsystem that reads it. Use a separate local counter when timing an independent effect.
- The byte-pointer declaration is partial typing, not proof that the whole system layout is known.
- Use named structure definitions when available; offset writes must match the exact game version.
- The full structure pointer and the interior D_800BCCC0 alias have different offset origins. Graphics-bank indices and gameplay state offsets must use the full pointer.
