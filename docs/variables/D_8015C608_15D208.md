## How it works

Save flags are packed bits: byte index flag_id / 8 and bit flag_id % 8. Native flag accessors provide the corresponding operations.

Signed 32-bit fish counters are at +0x110 for red, +0x114 for yellow and +0x118 for blue. Ushiwaka quest completion checks use counts 8, 5 and 3 respectively; active quest flags are 0x2A, 0x2B and 0x2C.

Adjacent runtime fields precede this symbol: signed 32-bit maximum HP at -0x28, current-HP byte at -0x21, and signed 32-bit runtime lives at -0x1C. A maximum HP greater than zero indicates loaded player state. The signed 32-bit saved lives copy is at +0x78.

The fresh-save initializer clears 0x304 bytes beginning here, seeds game defaults and copies the block to backup memory. An event flag ID n selects byte n>>3 and bit n&7.

Known 32-bit fields include recruited characters at +0x94,+0x98,+0x9C,+0xA0 and weapon levels at +0xA4 through +0xB0. The spawn room is a 16-bit field at +0x204, followed by rotation/coordinate fields from +0x208 through +0x210. Maximum health is referenced at -0x28 in adjacent runtime storage.

Use each field correct width. Changing persistent progression does not automatically update an existing actor, boss state machine or active doorway.

## Known values

### Packed flag values {#save-flag-value-semantics}

A flag ID selects one bit: byte offset = ID >> 3; bit index = ID & 7; mask = 1 << bit. The logical state 0/1 is not the value of the whole byte. Only documented nonnegative IDs should be used: the native helpers mask the computed byte index with 0xFF rather than checking the valid save-field range.

| Representation | Raw value | Meaning |
| --- | --- | --- |
| Normalized logical flag | `0` | Selected bit clear: named event/condition is not set. |
| Normalized logical flag | `1` | Selected bit set: named event/condition is set. Other bits in the byte are independent. |
| Native flag getter result | `0` | Selected mask was absent. |
| Native flag getter result | `1 << (ID & 7)` | Selected mask is present. This can be 1, 2, 4, 8, 16, 32, 64 or 128; normalize with != 0 when a boolean is needed. |
| Example: ID `0x033` (`51`) | Byte `0x06`, mask `0x08` | Benkei defeat/dialogue flag. The native getter returns 0 or 8, not necessarily 0 or 1. |
| Entire stored byte | `0x00` through `0xFF` | Up to eight independent flags coexist. Setting one flag must preserve all unrelated bits. |

### Encounter flag distinctions {#save-native-encounter-milestones}

Native death, reward, dialogue and controller milestones are separate bits. The Congo exit uses file_43 callbacks 08006174/080061C8/08006228 for its native wait and opening, not the generic key-padlock state machine. ## Usage example

```c
extern unsigned char D_8015C608_15D208[];

int blue_fish_count(void)
{
    char *save = (char *)D_8015C608_15D208;
    if (*(volatile int *)(save - 0x28) <= 0) return 0;
    return *(volatile int *)(save + 0x118);
}

int is_blue_fish_quest_active(void)
{
    return (D_8015C608_15D208[0x2C / 8] & (1u << (0x2C % 8))) != 0;
```

The example shows the documented native data layout or call sequence. Use it only while the relevant game state and resources are valid.

## Notes

- Preserve each field width. Negative offsets refer to adjacent runtime storage, not to entries in the save-flag array.
- Saved and runtime copies can differ during transitions; writing only one copy may be overwritten by later native synchronization.
- Offsets before the array are adjacent native storage, not elements of a C array declared here; native callers deliberately use address arithmetic.
- Flag changes can affect scripts and save progression without updating live actors. Use native actor transitions for bosses and active doors.
- Use the correct field width: recruitment/items are 32-bit, spawn coordinates are 16-bit, flags are packed bits.
