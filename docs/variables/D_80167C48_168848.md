`D_80167C48_168848` · **Variable**

Three pointers to native message-window allocations.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80167C48` | — | `ABSOLUTE_SYMS` |

## Signature

```c
extern void *D_80167C48_168848[3];
```

## How it works

Each array entry is a window pointer. The allocator stores its result here; cleanup clears the selected slot.

Check all three slots before claiming an idle shared dialog interface. Slot zero is used by the ordinary save-sign dialog.

The signed 16-bit animation state is at window +0x30. Opening uses states 1 through 3; closing uses states 5 and 6. A ready window and an absent window must be distinguished by checking the pointer.

Each window contains 120 native glyph records of 0x30 bytes, starting at window +0x198. The native allocator searches these records; bound a custom prompt and its labels to the available glyph capacity.

Each window has 120 glyph records of 0x30 bytes beginning at window +0x198. A record stores its type at +0x04, flags at +0x06, signed center coordinates at +0x08/+0x0A, float X/Y scales at +0x14/+0x18, and a copied low effect mask at +0x2C. The renderer combines the record center with the window screen position.

The native glyph insertion routine fills the first free record and advances the horizontal cursor at window +0x6E by glyph_width + 1. Printable ASCII maps to the game font by subtracting 0x20 from each character byte. The newline routine resets the horizontal cursor and advances the text line.

A native text effect can mark subsequently inserted glyphs to blink; the renderer toggles the title hidden bit every two rendered frames. Clear that insertion effect after adding the glyphs that should blink.

Text inset state is stored at window +0x50/+0x54; the inspected native window setup uses 10 horizontal and 7 vertical pixels. The per-glyph center is relative to this inset and cursor state.

## Known values

### Message-window animation state {#message-window-state}

Read the signed 16-bit field at offset +0x30 only after confirming a live window pointer. These state groups come from the native readiness helper; absence and readiness both require a separate pointer check.

| Stored state | Meaning |
| --- | --- |
| `1`–`3` | Opening animation |
| `5`–`6` | Closing animation |

## Notes

- The array contains pointers, not three contiguous 0x1818-byte windows.
- Do not dereference a freed slot or consider a null pointer a successfully opened window.
- The native text scale path includes additional coordinate adjustments; the meaning and safe range of non-unit scale values are not established here.
