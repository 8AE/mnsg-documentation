`D_8020D220_5C9130` · **Variable**

Native pointer storage for the current player's reusable broad-character resource buffer.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x8020D220` | — | `ABSOLUTE_SYMS` |

## Signature

```c
extern void *D_8020D220_5C9130[];
```

## How it works

The native resource initializer at 0x801DC630 reserves 0x18000 bytes from the scene resource arena and writes the buffer pointer at entry 0. The inspected initializer establishes only this one entry.

The character-resource loader at 0x801DC9C8 indexes this storage using the playable task's byte at +0x90, loads the broad file selected by D_80204020_5BFF30[character], and checks that its returned end pointer stays within the reserved 0x18000 bytes.

Player-owned visual constructors can bind this buffer as their broad-resource segment. It holds the currently loaded character data and can be overwritten during a character change.

## Usage example

```c
extern void *D_8020D220_5C9130[];

/* Read only after native player resource initialization in the live scene. */
const unsigned char *current_player_broad_buffer(void)
{
    return D_8020D220_5C9130[0];
}
```

Returns the single buffer entry established by the inspected initializer. The pointer does not grant ownership of the resource arena.

## Notes

- This is pointer storage, not the beginning of the character file itself. Dereference entry 0 to obtain the buffer.
- Only index 0 is established by the inspected initialization. Do not infer a four-character array or independent buffers from native indexed syntax.
- The address also appears in another overlay with a different ROM suffix. Preserve the complete _5C9130 symbol identity.
- A cached pointer can remain numerically equal while its character contents change. Resolve its resource identity and lifecycle before retaining a visual reference.
