`D_8016DAB4_16E6B4` · **Variable**

Pointer to the task currently executing in the native scheduler.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x8016DAB4` | — | `ABSOLUTE_SYMS` |

## Signature

```c
extern void *D_8016DAB4_16E6B4;
```

## How it works

Several helpers obtain their target implicitly from this global. func_8003521C_35E1C writes its AI callback at +0x0C, and func_80034ED4_35AD4 deletes this current task.

Code that invokes task callbacks outside their normal scheduler invocation must preserve the original context, set the intended task, detect deletion or context changes and restore the previous value.

## Known values

### Current task fields {#task-fields}

Offsets are relative to the current task pointer. The first callback/object fields belong to the shared task prefix. Actor-extension fields below apply to ordinary actor tasks; the playable-player task has a different +0x5C meaning.

| Offset | Storage type | Meaning |
| --- | --- | --- |
| `+0x08` | 32-bit callback slot | Pre/first callback slot. |
| `+0x0C` | 32-bit callback slot | AI/update callback slot. |
| `+0x10` | 32-bit callback slot | Post-update callback slot. |
| `+0x18` | 32-bit pointer | Render/model object. |
| `+0x5C` | `uint16_t` | Ordinary actor ID. Do not use this interpretation for the player task. |
| `+0x5E` | `uint16_t` | Ordinary actor entity ID. |
| `+0x68` | `uint32_t` | Ordinary actor status bitfield. |
| `+0x74` | `uint8_t` | Ordinary actor generation/identity byte. |
| `+0x8D` | `uint8_t` | Health field for the actor types that use this layout. |

### Known task masks {#task-bitmasks}

These masks belong to fields of the pointed-to task. They are not flags stored in D_8016DAB4_16E6B4 itself.

| Field | Mask (hex) | Mask (decimal) | Meaning when set |
| --- | --- | --- | --- |
| Status word at `+0x68` | `0x00000002` | `2` | Removal is pending. |
| AI/post callback slot at `+0x0C` / `+0x10` | `0x00800000` | `8388608` | Callback is disabled. Preserve the native callback representation when changing this bit. |

## Usage example

```c
extern void *D_8016DAB4_16E6B4;

int is_current_native_task(void *task)
{
    return task && task == D_8016DAB4_16E6B4;
}
```

The example shows the documented native data layout or call sequence. Use it only while the relevant game state and resources are valid.

## Notes

- A native callback can delete its task or replace the current-task pointer. Do not continue using stale task storage after such a change.
- Task addresses can be reused. Object pointer, actor ID and generation provide additional identity checks.
