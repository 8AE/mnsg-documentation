`D_80168504_169104` · **Variable**

Pointer to the next 64-byte fixed-point matrix submitted by native rendering.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80168504` | — | `ABSOLUTE_SYMS` |

## Signature

```c
extern unsigned char *D_80168504_169104;
```

## How it works

func_80016950 resets this pointer to the selected bank’s matrix array at bank offset 0x14C80. The stock array contains 540 matrices of 64 bytes each.

Native transform writers advance this cursor without checking its end. Per-node billboard handling can consume three submitted matrices; root transforms and camera setup consume additional matrices.

This final fixed-point matrix storage is separate from kind-2 CPU model caches and the native temporary floating-point transform stack.

## Usage example

```c
extern unsigned char *D_80168504_169104;

unsigned char *native_matrix_cursor(void) {
    return D_80168504_169104;
}
```

The example illustrates the native interface and its required state.

## Notes

- A matrix pointer may be emitted into a display list. Its data must use an address accepted by the graphics path and remain unchanged until that bank is reusable.
- Expanding CPU record storage or a capacity scalar does not expand the matrix array.
