`D_801FC668_5B8578` · **Variable**

Four character-indexed native body height values copied into the player task.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x801FC668` | `0x005B8578` | `.file_11` |

## Signature

```c
extern unsigned short D_801FC668_5B8578[4];
```

## How it works

This is an array of four unsigned 16-bit values in gameplay overlay .file_11, indexed by the native character byte: 0 Goemon, 1 Ebisumaru, 2 Sasuke, 3 Yae.

The native player collision initializer at 0x801CC454 reads this array with an unsigned halfword load and writes the selected value into task +0x3E.

The native body-contact test at 0x80033688 multiplies the unsigned task value by render-object scale Y before testing the body. These are unscaled dimensions, not world-space distances until the object scale is applied.

## Known values

### Character body height values {#character-body-height}

Unscaled unsigned 16-bit dimensions in the native character order. Multiply by the corresponding render-object scale for world-space dimensions.

| Character index | Character | Unscaled height |
| --- | --- | --- |
| 0 | Goemon | 200 |
| 1 | Ebisumaru | 160 |
| 2 | Sasuke | 140 |
| 3 | Yae | 180 |

## Usage example

```c
extern unsigned short D_801FC668_5B8578[4];

/* Requires the gameplay overlay to be loaded. */
float native_character_height(unsigned int character, float scale_y)
{
    if (character >= 4u || scale_y <= 0.0f) return 0.0f;
    return (float)D_801FC668_5B8578[character] * scale_y;
}
```

The example illustrates the native interface and its required state.

## Notes

- Use only while the gameplay overlay is loaded, and bounds-check the character index.
- This table configures native body-contact geometry. Assigning these dimensions to a task does not create a solid movement resolver or register a new actor by itself.
