`D_800C7AE3` · **Variable**

Native system byte held while scripted movement supplies player input.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x800C7AE3` | — | `ABSOLUTE_SYMS` |

## Signature

```c
extern unsigned char D_800C7AE3;
```

## How it works

This byte occupies full system-structure offset +0x3AE23, at runtime address 0x800C7AE3. It is stored directly; it is not a pointer.

The player move-toward helper at 0x801CF770 sets bit 0 and supplies a synthetic stick magnitude and direction. Eocs player-input playback creation also sets the byte to 1.

The Eocs playback update at 0x80224324 holds the byte at 1 while playback is active, then clears it to 0, clears the selected player input word, reports completion, and deletes the playback task.

Scripted input can remain active while the normal native world-collision update runs. Check this state separately when an additional obstacle must not interfere with scripted player positioning.

## Known values

### Verified scripted input values {#scripted-input-values}

Native move-toward sets bit 0; Eocs playback stores 1 during playback and clears the whole byte on completion. Other bit meanings are not established.

| Raw value (hex) | Raw value (decimal) | Meaning |
| --- | --- | --- |
| `0x00` | `0` | Cleared scripted-input ownership after playback completion. |
| `0x01` | `1` | Scripted player-input ownership used by move-toward and playback paths. |

## Usage example

```c
extern unsigned char D_800C7AE3;

int scripted_player_input_is_active(void)
{
    return D_800C7AE3 != 0;
}
```

The example illustrates the native interface and its required state.

## Notes

- Nonzero indicates native scripted-input ownership in the inspected movement paths; it is not a catalog of every cinematic or camera sequence.
- Leave writes and clearing to the native script lifecycle. Do not infer scripted input from an idle action or zero velocity.
