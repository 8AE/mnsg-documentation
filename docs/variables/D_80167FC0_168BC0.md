`D_80167FC0_168BC0` · **Variable**

Dynamic scene-resource registry with 48 accepted ID slots and an append cursor; memory capacity requires a separate bound.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x80167FC0` | — | `ABSOLUTE_SYMS` |

## Signature

```c
extern SceneResourceEntry D_80167FC0_168BC0[SCENE_RESOURCE_ENTRY_COUNT];
```

## How it works

The loader accepts 48 file-ID slots at 0x80167FC0 + 8 * index for indices 0 through 47. Each 8-byte record contains a 16-bit file ID, a retained halfword and a 32-bit data value. A zero file ID terminates the resident list; its data value supplies the next allocation destination.

A new load writes the file ID into the first zero slot, loads and registers the file, then writes a following zero-ID sentinel with the next 64-byte-aligned cursor. Loading the final accepted slot writes that sentinel at 0x80168140 and its cursor at 0x80168144, which are adjacent loader scratch globals. They are outside the accepted ID scan range.

func_80013B14_14714 returns zero for a full ID scan and does not evict entries. The 48-ID bound does not enforce arena capacity or reserve resources for later events.

Ordinary File11 cold setup reserves the world bank prefix 0x80304000 through 0x803214FF and starts dynamic appends at 0x80321500. It uses four 0x1000-byte work buffers beginning at 0x80305500 and a 0x18000-byte player buffer at 0x80309500.

The boot File10 allocation spans 0x80304000 through exclusive end 0x80594000. An ordinary-world extension may adopt that end as an explicit conservative cache policy; the native loader itself does not check it. Preserve the reserved prefix and verify the live retained cursor, file-allocation extents and alignment before each append.

Room transitions can truncate the registry at a retained entry index before loading donor and actor resources. Count the actual retained prefix together with appended IDs; an authored resource list alone is not the complete occupancy.

## Known values

### Resident resource entry fields {#resource-entry-fields}

The loader accepts 48 file-ID slots, each 8 bytes. Scan only within those slots until the first zero file ID; its data value gives the next allocation destination. The loader writes the full-list sentinel into adjacent scratch storage outside this accepted scan range. ID-slot capacity does not establish heap capacity.

| Offset | Storage type | Meaning |
| --- | --- | --- |
| `+0x00` | `uint16_t` | File ID. Zero terminates the occupied entries. |
| `+0x02` | 2 bytes | Uninterpreted padding/field. |
| `+0x04` | 32-bit pointer | Loaded data base for a nonzero file ID; next free arena position for the first zero-file-ID entry. |

## Usage example

```c
#define SCENE_RESOURCE_ENTRY_COUNT 48
typedef struct SceneResourceEntry {
    unsigned short file_id, padding;
    unsigned char *data;
} SceneResourceEntry;

extern SceneResourceEntry D_80167FC0_168BC0[SCENE_RESOURCE_ENTRY_COUNT];

/* Inspect only after the native stage resource registry is initialized. */
void *scene_arena_cursor(void) {
    for (int i = 0; i < SCENE_RESOURCE_ENTRY_COUNT; ++i) {
        if (D_80167FC0_168BC0[i].file_id == 0)
            return D_80167FC0_168BC0[i].data;
    }
    return 0;
}
```

Scans only the 48 accepted records and reads the first zero-ID cursor. Null means no sentinel was found within that range; it does not establish heap capacity.

## Notes

- 48 accepted resource IDs and a separate bounded memory region are independent checks. A full list has no sentinel inside these 48 accepted records; the example returns null in that case.
- Do not write into the ordinary-world reserved prefix or extend its cache using unverified gaps between native and host allocations.
- The 0x80594000 policy applies only to the inspected ordinary File11/File12 world layout. Other modes, substituted resources and relocated banks need their own allocation contract.
- Reacquire registry-backed values after scene truncation or reload. Preserve opaque resource tags expected by native consumers.
