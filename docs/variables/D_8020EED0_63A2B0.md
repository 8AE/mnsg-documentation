`D_8020EED0_63A2B0` · **Variable**

Pointer to the shared Impact-battle state used by Thaisamba.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x8020EED0` | — | `ABSOLUTE_SYMS` |

## Signature

```c
extern void *D_8020EED0_63A2B0;
```

## How it works

Known offsets are signed 32-bit boss HP at +0x60, boss task pointer at +0x1D8, model task pointer at +0x1E0 and combat-paused byte at +0x2C0.

A live battle requires a current state instance, the expected boss task, a model task, positive boss health and no combat pause. This state belongs to the dedicated Impact-battle overlay, separate from the ordinary room-actor pipeline.

## Known values

### Impact battle-state fields {#impact-state-fields}

These offsets are relative to the live Impact battle-state pointer. The state is meaningful only during the corresponding battle mode.

| Offset | Storage type | Meaning |
| --- | --- | --- |
| `+0x060` | `int32_t` | Boss health. The battle helper tests whether it is greater than zero. |
| `+0x1D8` | 32-bit pointer | Boss task. |
| `+0x1E0` | 32-bit pointer | Boss model task. |
| `+0x2C0` | `uint8_t` | Combat pause gate: zero means not paused by this gate; nonzero means paused. |

## Usage example

```c
extern void *D_8020EED0_63A2B0;

int impact_boss_combat_active(void)
{
    char *s = (char *)D_8020EED0_63A2B0;
    return s && *(volatile int *)(s + 0x60) > 0 &&
        *(volatile unsigned char *)(s + 0x2C0) == 0 &&
        *(void **)(s + 0x1D8) && *(void **)(s + 0x1E0);
}
```

The example shows the documented native data layout or call sequence. Use it only while the relevant game state and resources are valid.

## Notes

- Do not dereference a retained state pointer after the Impact overlay is unloaded.
