`D_8020EED0_63A2B0` · **Variable**

Shared state for the four dedicated Impact boss encounters, including camera aim, grappling-hook control and reeling.

| Runtime address | ROM address | Section |
| --- | --- | --- |
| `0x8020EED0` | — | `ABSOLUTE_SYMS` |

## Signature

```c
extern void *D_8020EED0_63A2B0;
```

## How it works

Known offsets include signed 32-bit boss HP at +0x60, ammunition at +0x64 and mech HP at +0x68; the battle-manager task at +0x1BC, world/HUD task at +0x1C4, native input task at +0x1C8, boss task at +0x1D8, boss model object at +0x1E0 and combat-paused byte at +0x2C0.

Active combat requires a current state instance, the expected boss task and model, positive boss health and no combat pause. The native task graph also remains live during introductions and victory sequences. This state belongs to the dedicated Impact-battle overlay, separate from the ordinary room-actor pipeline.

During ordinary active combat, file_13 FUN_801CC10C smooths local aim angles at +0x04/+0x08 into +0x74/+0x78, then computes camera position at +0xA0/+0xA4/+0xA8 and target at +0xAC/+0xB0/+0xB4. The field at +0xBA is the native projection/FOV halfword. These are camera presentation fields, distinct from the boss and mech world poses.

The native input interpreter reads held and newly pressed controller buttons separately. Attack requests at +0x141 and +0x145 can remain pending across callbacks before the dispatcher creates their native limb or projectile task. The primary cursor is at +0x00 and the shooting cursor is at +0x0C; they refer to the same task in the ordinary one-controller configuration.

Native guard release and special-fist controls read controller state again from their own task callbacks, outside the main input interpreter. A display-only model does not supply an attack collider or a projectile interception contact.

The grappling arm opens through FUN_801D9704/FUN_801D9730; only later does FUN_801D9DA8 launch its child hook. That launch reads the primary cursor task at +0x00 and its object X/Y rotation at +0x14/+0x16. The child hook keeps its arm-task pointer at +0x90; the arm keeps its child at +0x88.

A latched hook stores the target boss task at state +0x174. The boss reeling callbacks FUN_801E9624, FUN_801F5F0C and FUN_801FED3C read primary-controller pressed bits at system +0x3B07C with 0x18-byte stride, independently of the mech input interpreter. The accepted mash mask is 0xC030 (A/B/L/R); R also ends the struggle timer. Each tick subtracts 0.5 from task +0xA0, a press adds 9 or 11 depending on the native stick-direction check, and the meter is clamped to 0..100 then exposed as an integer at state +0x70.

FUN_801DA3CC rebuilds the visible grappling chain with native model commands from table 0x80209CF0: 0x4800A380, 0x4800A460, 0x4800A540, 0x4800A620, 0x4800A700, 0x4800A7E0, 0x4800A8C0 and 0x4800A9A0, all in file 0x4A8.

Aim is not consumed only at input dispatch. The punch/arm updater FUN_801D9030 rereads yaw and pitch at state +0x04/+0x08 on every animation update (MIPS 0x801D93D4..0x801D9448), despite those reads being omitted from incomplete pseudocode. Guard placement FUN_801DD3DC and delayed laser initialization FUN_801DC194 also read shared aim. The Ryo constructor FUN_801DAFCC reads the secondary cursor task at state +0x0C. A task can therefore read aim after its creating input callback has returned.

Taisamba 2 uses encounter selector 2 and boss task ID 0x5A. Arena displacement is accumulated as float X/Y/Z at state +0x178/+0x17C/+0x180 and integrated into the arena origin at +0x184/+0x188/+0x18C by FUN_801D0C70. The integrator clears pending displacement each update; the vertical origin is clamped to 0..400 before integration. These world fields are separate from camera aim and projection.

Taisamba 2 ascent callback FUN_801F1788 writes +0x17C = 1.0 until the arena height reaches 400, then clears the ascent request at +0x2C5 and enters aerial combat. FUN_801F71DC selects ground or air behavior from whether +0x188 is zero. The root movement helper FUN_801F7214 applies pending arena displacement to its model.

The Taisamba 2 root task private area mixes scalar fields and pointers. Root +0x74 is vertical velocity. Root +0x9C holds a returning-weapon task pointer during FUN_801F3950, which reads weapon task ID +0x5C, but contains an angle in the grappling setup. Root +0xDC holds the last collision task; FUN_801F6660 reads that task's +0x18 model, +0x70/+0x74/+0x78 velocity, model XYZ position and Y rotation. Copying these pointer words between task graphs is invalid.

Taisamba 2 combo-grab callback FUN_801F5710 positions the boss from state yaw +0x04 and waits for the action timer byte +0x14F to reach zero. Its release callback FUN_801F58AC reads yaw/pitch +0x04/+0x08 to initialize knockback velocity. These aim reads occur on the boss task, separately from the attacking limb updater.

Taisamba 2 ground/air death reactions FUN_801F4B4C and FUN_801F5550 set the completion byte at state +0x2C4 to 1 before switching to the outro callback FUN_801EF924. The completion signal and phase transition are separate native writes.

Balberra uses encounter selector 3 and task ID 0x78. Its root constructor func_80200200_62B5E0 creates body parts and two sliding missile pods. Actual root HP is a signed word at task +0xAC; func_8020407C_62F45C republishes it at state +0x60. Separate gun, beam, deck-cannon and rocket-tube tasks also have HP at +0xAC, damage flash at +0xB0 and native destruction callbacks. The rocket index at task +0x90 distinguishes the six tubes; multiple tubes share task ID 0x71.

Attachment helper func_80203F5C_62F33C stores a local parent task at child +0xB4 and parent model at +0xB8, followed by float local offsets at +0xBC/+0xC0/+0xC4. These parent pointers are not scalar pose fields. Sliding missile pods own their own cannon and rocket descendants.

Balberra and D'Etoile allocate an auxiliary block through D_8020EF40_63A320. Bytes +0x04..+0x12 contain part commands, destroyed-part flags and drone state. For D'Etoile, +0x14..+0x813 contains 64 pose-history records of 32 bytes, not a task-pointer list: position XYZ, rotation XYZ encoded as floats, segmented model ID and animation frame. Byte +0x814 is the local circular write index. Bytes +0x815/+0x816/+0x817 control afterimages, shield commands and charge glow. func_80205FC8_6313A8 writes history; func_802061B8_631598 reads delayed records for the afterimages.

In the standard story handoff, Balberra callback func_80201C7C_62D05C invokes func_802085B0_633990, which clears completion byte +0x2C4 and increments the native encounter selector at system +0x3ADF4. It then removes old children and assigns func_801FAEB0_626290 to the existing root task. That initializer assigns D'Etoile task ID 0x64. The root address can therefore remain unchanged while the encounter changes.

D'Etoile keeps the last collision task at root +0xDC. Carry callback func_801FF528_62A908 dereferences that task's +0x18 model and consumes its position, velocity and Y rotation. Release callback func_801FE66C_629A4C reads global aim. Initial grapple callback func_801FE964_629D44 reads normalized primary-controller X at system +0x3B084 with stride 0x18; func_801FED3C_62A11C performs the subsequent A/B reeling. Balberra has no equivalent A/B reeling reader.

D'Etoile shield callback func_802065B8_631998 consumes the +0x816 command each update and normally clears it. A deflection instead writes 0xFF, disables collision, sets a 28-tick timer and switches to func_8020679C_631B7C. That callback animates a detached spin before restoring the shield attachment. The resulting child state remains meaningful after the command pulse is gone.

## Known values

### Impact battle-state fields {#impact-state-fields}

These offsets are relative to the live Impact battle-state pointer. The state is meaningful only during the corresponding battle mode.

| Offset | Storage type | Meaning |
| --- | --- | --- |
| `+0x060` | `int32_t` | Boss health. The battle helper tests whether it is greater than zero. |
| `+0x1D8` | 32-bit pointer | Boss task. |
| `+0x1E0` | 32-bit pointer | Boss model/display object (the boss task is at +0x1D8). |
| `+0x2C0` | `uint8_t` | Combat pause gate: zero means not paused by this gate; nonzero means paused. |
| `+0x178/+0x17C/+0x180` | `float[3]` | Pending arena displacement (X/Y/Z); integrated and cleared each native world update. |
| `+0x184/+0x188/+0x18C` | `float[3]` | Arena origin (X/Y/Z). Taisamba 2 uses Y height to select ground versus aerial behavior. |
| `+0x2C5` | `uint8_t` | Taisamba 2 ascent request. Set by the low-health ground reaction and cleared when ascent reaches its upper height. |

## Usage example

```c
extern void *D_8020EED0_63A2B0;

int impact_boss_combat_active(void)
{
    char *s = (char *)D_8020EED0_63A2B0;
    return s && *(volatile int *)(s + 0x60) > 0 &&
        *(volatile unsigned char *)(s + 0x2C0) == 0 &&
        *(void **)(s + 0x1D8) && *(void **)(s + 0x1E0);
}
```

The example shows the documented native data layout or call sequence. Use it only while the relevant game state and resources are valid.

## Notes

- Do not dereference a retained state pointer after the Impact overlay is unloaded.
